> 本文是决策页面（decision page）的完整设计契约。决策页为 MOS（最小应急起降带）规划工作区：跑道俯视图 + 损毁目标列表 + 候选起降方案 + 修复优先级 + 算法参数。每个交互控件拥有稳定 `DEC-*` ID 与全字段规格。HTML 原型实现必须以本文为唯一依据。所有视觉值取自 `design-system.md`。

CURRENT 来源：决策页在 CURRENT Qt 客户端中**未作为独立页面实现**。CURRENT 主窗口仅渲染态势页，导航栏点击"决策"仅高亮不路由（见 `application-shell.md` 第 3.2 节）。与决策页相关的 CURRENT 锚点：

- `src/MainWindow/DecisionView.cpp`：空壳类，`setupUi` 未实现，未被 `MainWindow` 实例化。
- `src/MainWindow/DecisionSuggestionPanel.cpp`：态势页右面板下段只读"模拟决策建议"子组件。
- `include/Core/Data/Types.h`：`TargetType`/`ThreatLevel`/`TargetStatus` 等枚举。

MOS 功能依据：`docs/dev/architecture-uxo-recognition-and-mos.md`（架构师 V1.0 设计），包含 `MOSPlanner` 算法（Y 轴离散化 + X 轴扫描线）、`MOSDataModels.h`（`RunwayModel`/`DamagePoint`/`MOSResult`/`MOSPlanParams`）、`MOSView`（QPainter 2D 可视化）。本页面是该架构设计的 UI 原型呈现。

## 1. 页面概述

决策页面是 MOS 起降带规划工作区（导航 `DEC-NAV-03` 默认选中）。一屏呈现：左侧损毁目标列表（弹坑/UXO，带威胁/状态标记），中心上方跑道 3000m×50m 俯视图（叠加弹坑圆圈/UXO 圆圈/MOS 矩形），中心下方算法参数表单（MOSPlanParams），右侧候选起降方案卡片 + 选定详情 + 修复优先级列表 + 决策草案。所有数据来自本地固定模拟 fixture（4 个损毁点 + 3 档方案），选择方案只产生草案状态，无执行语义。

| 区域 | 位置 | 内部组件 | CURRENT 主控件 |
|------|------|----------|----------------|
| 壳 | 顶部/左侧/底部 | 菜单栏、MOS工具栏、导航栏、状态栏 | `application-shell.md` 第 3 至 6 节（未实现页面路由） |
| A | 左面板 260px | 损毁目标列表（4 张模拟目标卡片：弹坑/UXO） | 未实现（`DecisionView` 空壳） |
| B | 中心区上 flex:1 | 跑道俯视图（跑道 + 4 个目标圆圈 + 3 个 MOS 矩形 + 图例 + 缩放） | 未实现；`MOSView` 架构设计已定义 QPainter 自绘 |
| B' | 中心区下 | 算法参数栏（MOSPlanParams，10 个可编辑输入 + 2 个只读 + 校验状态 + 重新规划） | 未实现；`MOSConfigPanel` 架构设计已定义 |
| C | 右面板 380px | 候选方案卡片×3 + 选定详情 + 修复优先级 + 决策草案 | 未实现 |

页面固定尺寸 1920×1080。

## 2. 应用壳元素

### 2.1 导航栏

固定宽 80px，背景 `--color-bg`，右侧 1px `--color-border` 边框。结构与态势页一致：UXO logo（高 40px，主色，18px 加粗，字间距 2px，居中）-> 16px 间距 -> 6 个导航项 -> 弹性留白。每个导航项高 56px，左侧 3px 透明边框，图标 `◎` + 文字双行，字号 `--font-size-caption`。选中态：背景 `--color-selection`、主色左边框 3px、主文本色、加粗。

| ID | 标签 | 默认 | 说明 |
|----|------|------|------|
| `DEC-NAV-LOGO` | UXO | 仅展示 | 不可交互 |
| `DEC-NAV-01` | 态势 | - | 点击仅切换高亮，不路由 |
| `DEC-NAV-02` | 探测 | - | 同上 |
| `DEC-NAV-03` | 决策 | 选中 | 当前页面 |
| `DEC-NAV-04` | 设备 | - | 同上 |
| `DEC-NAV-05` | 统计 | - | 同上 |
| `DEC-NAV-06` | 配置 | - | 同上 |

### 2.2 菜单栏

高 30px，背景 `--color-menu`。4 个顶级菜单：文件(F) / 视图(V) / 工具(T) / 帮助(H)。菜单项为可点击文本，hover 背景 `--color-border`。原型不实现下拉弹出层。

### 2.3 MOS 工具栏

高 40px，背景 `--color-toolbar`。与态势页工具栏不同，决策页工具栏承载 MOS 专用操作：

| ID | 标签 | 类型 | 位置 | 用途 | 默认态 | 点击结果 |

### 2.4 状态栏

| ID | 标签 | 用途 |

| `DEC-SB-SIM` | [模拟模式] | 只读，橙色 |

## 3. 区域 A：左面板 -- 损毁目标列表

宽 260px 固定，背景 `--color-panel`，右侧 1px 边框。面板头高 36px，标题"[模拟] 损毁目标列表"。

### 3.1 目标列表 `DEC-LP-TARGET-LIST`

弹性填充，`overflow-y: auto`。4 张模拟目标卡片：

| 目标 ID | 类型 | 威胁 | 状态 | 坐标 | 尺寸 |
|---------|------|------|------|------|------|
| 弹坑-001 | 弹坑 | 高 | 已发现 | 1200,25 | Ø8m |
| UXO-003 | 未爆弹 | 高 | 已发现 | 1500,30 | 影响45m |
| 弹坑-005 | 弹坑 | 中 | 已修复 | 800,15 | Ø6m |
| UXO-007 | 未爆弹 | 中 | 已发现 | 2200,35 | 影响30m |

卡片背景 `#2D2D2D`，1px `--color-border` 边框，圆角 `--radius-control`，内边距 10px，`cursor: pointer`。选中态：蓝色边框 `#5B9BD5` + 背景 `--color-selection`。

卡片内部三行：
- 第 1 行：ID（等宽字体 12px）+ 类型（粗体 13px）+ 威胁徽章
- 第 2 行：状态文字 + 坐标（等宽字体）
- 第 3 行：尺寸（等宽字体）

**功能依据**：`DamagePoint` 列表，架构 `MOSDataModels.h` 定义的算法输入。每个目标在跑道俯视图上有对应的圆圈标注。

**交互**：点击卡片 -> 卡片高亮 + 跑道图对应圆圈脉冲高亮 + 状态栏更新当前决策目标。

## 4. 区域 B：中心区 -- 跑道俯视图 + 算法参数

中心区 flex 列布局，上下分栏：上方跑道俯视图（flex:1）+ 下方算法参数栏（固定高度）。

### 4.1 跑道俯视图 `DEC-CE-RUNWAY`

**功能依据**：`MOSView`（架构 1.3 节，QPainter 自绘跑道/弹坑/安全区/MOS 矩形，支持缩放/平移）。

跑道标题"跑道 3000m × 50m [模拟]"。跑道容器背景 `#1a2a1a`，内边距 20px 40px。跑道为灰色长条 div（背景 `--color-runway` #3D3D3D，边框 1px solid #555），宽 100%，高 200px。

跑道内有 7 条刻度线（0%/16.67%/33.33%/50%/66.67%/83.33%/100%），底部标注距离。

#### 目标圆圈（4 个）

每个左面板目标在跑道图上有对应圆圈，位置按坐标/3000m 换算百分比：

| 目标 | 跑道位置 | 视觉半径 | 颜色 | 标注 |
|------|---------|---------|------|------|
| 弹坑-001 | 40% | 20px | 红色半透明 `rgba(255,82,82,0.3)` + 红边框 | 弹坑-001 Ø8m |
| UXO-003 | 50% | 30px | 黄色半透明 `rgba(255,235,59,0.25)` + 黄边框 | UXO-003 45m |
| 弹坑-005 | 27% | 18px | 灰色虚线 + ✓ | 弹坑-005 已修复 |
| UXO-007 | 73% | 22px | 黄色半透明 + 黄边框 | UXO-007 30m |

圆圈 `cursor: pointer`，hover 阴影。选中态：`box-shadow: 0 0 16px` 对应颜色 + 边框 3px + 脉冲动画 `@keyframes pulse` 1.2s infinite。

**交互**：点击圆圈 -> 左面板对应卡片高亮（双向联动）。

#### MOS 矩形（3 个）

三个方案矩形叠加在跑道上，绝对定位 div：

| 方案 | 跑道位置 | 宽度 | 高度 | 边框 | 填充 | 标注 |
|------|---------|------|------|------|------|------|

#### 图例

跑道下方左侧，6 项色块+文字：弹坑（红圆）/ UXO（黄圆）/ 已修复（灰虚线圈）/ 方案1（橙虚线矩形）/ 方案2（绿实线矩形）/ 方案3（蓝虚线矩形）。

### 4.2 算法参数栏 `DEC-CE-PARAMS`

**功能依据**：`MOSPlanParams`（架构 `MOSDataModels.h` 定义的可配置参数）+ `MOSConfigPanel`（架构 1.3 节定义的参数配置面板）。

面板背景 `--color-panel`，1px 边框，圆角，内边距 10px 12px。三段结构：标题行 + 参数网格 + 底部状态行。

标题行："算法参数 [模拟]" + "恢复默认值"按钮。

参数网格 6 列，12 个字段：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 跑道长度 (m) | 可编辑 | 3000 | `RunwayModel.length` |
| 跑道宽度 (m) | 可编辑 | 50 | `RunwayModel.width` |
| 最小起降长度 (m) | 可编辑 | 460 | `MOSPlanParams.minLength` |
| 最小起降宽度 (m) | 可编辑 | 15 | `MOSPlanParams.minWidth` |
| 安全系数 K | 可编辑 | 1.2 | UXO 安全距离公式 D = K × W^(1/3) |
| 扫描步长 (m) | 可编辑 | 1 | Y 轴离散化步长 |
| 回填速率 (m³/h) | 可编辑 | 50 | 弹坑修复工时计算 |
| UXO 工时 (h/个) | 可编辑 | 8 | UXO 排除固定工时 |
| 扩展系数 | 可编辑 | 1.5 | 弹坑可见半径扩展 |
| 方案档位数 | 可编辑 | 3 | 递进方案数量（2~5） |
| 损毁点总数 | 只读 | 4 | 当前场景统计 |
| 已修复数 | 只读 | 1 | 当前场景统计（绿色） |

输入框：高 26px，背景 `--color-bg`，1px `--color-border` 边框，圆角，内边距 0 8px，等宽字体 13px。focus 边框 `--color-border-focus`。

底部状态行：左侧"面积单调递增校验: ✓ 通过 (6900 -> 9360 -> 13000)"，右侧"[↻ 重新规划]"主按钮。

**功能依据**：面积单调递增校验是架构定义的 `MOSPlanResult` 校验标志（方案 1->2->3 面积应单调不降）。

## 7. 交互流程

### 7.1 目标选择流程

1. 用户在 `DEC-LP-TARGET-LIST` 单击目标卡片。
2. 卡片高亮（蓝色边框）。
3. 跑道图对应圆圈脉冲高亮（box-shadow + 边框加粗）。
4. 状态栏 `DEC-SB-TARGET` 更新为目标 ID + 威胁等级。

### 7.2 方案选择流程

1. 用户点击候选方案卡片或工具栏方案切换按钮。
2. 方案卡片高亮选中。
3. 跑道图对应 MOS 矩形边框加粗 + 发光。
4. 选定详情大数字更新。
5. 决策草案方案名和起降带信息更新。

### 7.3 参数修改流程

1. 用户在算法参数栏修改输入框值。
2. 点击"重新规划"按钮。
3. 原型模拟：刷新方案数据（实际算法调用属后续实现）。

### 7.4 草案确认流程

1. 用户点击"确认选定方案"。
2. 草案状态从"待确认"变为"已确认"。
3. 仅记录状态，不执行处置、不下发任务。
