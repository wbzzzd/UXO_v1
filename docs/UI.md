# 指挥席客户端 UI 设计与实现状态

版本：V0.2 草稿
状态：待评审

## 1. 文档作用

- TARGET UI 来自产品需求、SRS 和旧 UI 设计中的有效用户流程，用于指导开发。
- CURRENT 状态来自源码和 UI 测试，用于说明哪些界面真正可用、哪些是半成品。
- 控件存在不等于功能完成；必须追踪到被消费的信号和可观察结果。

NEXT 使用单一指挥席用户，所有模拟操作和结果必须明确标注“模拟”或“演示”。

## 2. TARGET UI 目标

根据 SRS《排弹抢修指挥系统》v1.0 第 3.4.2 节“可视化呈现”、3.4.3 节“交互功能”、3.5 节“决策逻辑模块”、3.6 节“排爆处置模块”、3.7 节“插件模块”、7.2 节“界面需求” 和旧 UI 设计，指挥席客户端最终需要支持：

- 查看目标、任务、设备、告警和态势信息。
- 选择目标并查看完整详情和识别结果。
- 查看决策依据、候选方案和资源约束。
- 指派设备、确认任务并监控执行反馈。
- 查看操作日志、告警和历史结果。
- 清楚区分正常、加载、空、错误、降级和模拟状态。

真实设备控制台、真实排爆命令和安全执行链不属于当前仓库直接实现范围。

## 5. CURRENT 可完成的 UI 流程

```text
启动并看到“模拟模式”
  -> 在目标表选择唯一目标
  -> 目标表、流程面板和决策状态显示“已发现”
  -> 依次点击模拟确认、模拟处置、模拟完成
  -> 三处状态同步变化
  -> 操作日志按顺序显示四条记录
```

`simulation_workflow_ui` 自动验证上述流程。它不验证 3D 渲染结果、导航、视频、任务分配、设备联动、告警交互、紧急停止、配置或历史功能。离屏运行中出现的 Qt3D 上下文警告也不会使该测试失败。

## 6. TARGET：NEXT UI 需求

NEXT UI 来自 `PRODUCT.md` 的完整本地模拟指挥环需求，不从当前控件反推：

`PRODUCT.md` 第 9 节统一管理需求 ID 与状态；本文档只定义 UI 必须提供的可见结果。

| 产品需求 | UI 必须提供的结果 |
|----------|------------------|
| REQ-001 | 所有页面显示同一模拟会话状态，不出现相互矛盾的目标/任务/设备状态 |
| REQ-002 | 用户能选择目标和可用设备，为该目标对应的待执行模拟任务提交指派；无效选择得到明确原因 |
| REQ-003 | 用户能观察任务从指派到执行、完成，设备忙闲和目标状态同步变化 |
| REQ-004 | 目标、任务、设备、态势、决策和日志在一次操作后同步反馈 |
| REQ-005 | 新模拟会话加载后，各面板呈现同一份可复现的本地场景；本需求不新增用户重置入口 |
| REQ-006 | 用户能看到选择、指派、执行、完成和拒绝操作的完整本地日志 |

## 7. TARGET 设计尚未完成的内容

以下是 UI 设计必须继续补充的内容，不属于当前已实现事实：

- NEXT 的页面和导航信息架构。
- 目标选择、设备选择和任务指派的页面布局与交互顺序。
- 任务执行、失败、取消和完成状态的视觉反馈。
- 空场景、无可用设备、非法指派和状态冲突的错误表现。
- 当前占位菜单、工具栏和孤儿页面的保留、删除或重新设计决定。
- 1280×720、1920×1080 和目标 4K 三屏环境的布局验收规则。

在这些内容经用户评审前，`UI.md` 不能作为 NEXT 页面实现计划。

## 8. 通用视觉基线

旧 UI 设计中的颜色、字号和间距可作为来源资料；当前代码的 `GlobalStyle` 是实现事实。正式视觉规范需要在 NEXT 页面设计确认后统一整理。

当前最小约束：

- 模拟操作和结果必须明确标注“模拟”或“演示”。
- 状态颜色不能作为唯一信息，必须同时提供文字。
- 不显示没有行为且会误导用户的危险控制。
- 可点击控件必须有明确反馈；纯标签不得伪装成工具按钮。
- 页面必须定义正常、空、加载、错误和禁用状态。
