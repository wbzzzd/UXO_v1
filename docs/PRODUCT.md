## 1. 产品定义

排弹抢修指挥系统是面向空军场站的指挥席客户端软件，用于在跑道遭受打击后完成未爆弹识别、态势研判、处置决策与抢修恢复的指挥闭环。

当前仓库实现的是该系统的指挥席客户端 `UXOMissionControl`，技术栈为 Qt 5 / CMake / C++17 桌面程序。本文件区分三层事实：

- **TARGET**：SRS 描述的完整目标系统，含真实探测、AI 识别、远程排爆控制与数据库持久化。
- **CURRENT**：已交付的模拟演示 MVP，仅本地内存数据，无任何真实设备接入。
- **NEXT**：把当前模拟工作流打磨为"可用指挥环演示"的方向草稿，不构成实施承诺。

## 2. 用户角色

来源：SRS 2.4。

| 角色 | 职责 | CURRENT 是否覆盖 |
|------|------|------------------|
| 指挥员 | 任务调度、指令下达、态势研判 | 部分。可查看态势与决策建议，无真实指令下达 |
| 操作员 | 设备操控、现场处置、告警处理 | 部分。仅模拟工作流面板可推进目标状态 |
| 维护员 | 系统配置、故障处理、数据管理 | 未覆盖。`config/` 仅静态文件 |

`[Q?]` 是否需要拆分操作员子角色（探测操作员 vs 处置操作员）。

## 3. 端到端指挥环

TARGET 系统的完整闭环（来自 SRS 3.1 至 3.6）：

```
探测采集 -> 目标识别 -> 信息标注 -> 态势融合 -> 决策规划 -> 处置执行 -> 效果评估
   |          |          |          |          |          |          |
 全域多     AI 图像    GIS 标注    三维态势    威胁评估    远程控制    实时反馈
 传感器    多源融合    三维渲染    实时更新    路径规划    排爆机器人
```

CURRENT 实现的闭环只覆盖中间一环的模拟切片：

```
模拟场景加载 -> 目标列表展示 -> 选中目标 -> 状态推进 -> 操作日志追加
   (DemoScenario     (LeftPanel)    (Workflow)   (Detected->      (内存有序
    Provider)                                       Confirmed->      日志)
                                                    Disposing->
                                                    Disposed)
```

NEXT 草稿方向（第 8 节）的目标是把这条模拟切片补成"可演示的完整指挥环"。

## 5. CURRENT 发布范围

### 5.1 范围

- 启动 `UXOMissionControl` 显示标题为"排弹抢修指挥系统 V1.0"的主窗口。
- 加载本地模拟演示场景：1 个目标、1 个任务、2 个模拟设备。
- 主窗口左侧模拟工作流面板可选中目标并推进 `Detected -> Confirmed -> Disposing -> Disposed` 状态。
- 每次状态变更按时间顺序追加到内存操作日志。
- 决策建议面板与设备状态面板只读展示模拟数据，不发起真实控制。
- 4 个 CTest 用例覆盖启动可见性、场景提供器、工作流功能与 UI 行为。

### 5.2 非目标

- 不接真实探测设备、无人机、排爆机器人。
- 不发送任何真实控制指令。
- 不实现 AI 识别、多源融合、路径规划、殉爆计算。
- 不写入真实数据库，不持久化，不接入外部通信链路。
- 不实现用户认证、权限、加密、日志审计的真实逻辑（`Application::initialize()` 中相关初始化为占位返回成功）。
- 不修复已知 P2 问题：1280×720 窗口最小尺寸下 `DecisionSuggestionPanel` 底部约 5px 溢出。

### 5.3 验证

最近一次构建与测试在 `uxo-dev` 环境下完成，结果：构建通过，CTest 4/4 通过。命令见 `docs/dev/build-and-run.md`。

## 7. NEXT 草稿方向

来源：`mvp-scope.md` 优先顺序第 3 至 5 项。本节为方向草稿，不是实施承诺。

把当前模拟切片扩展为"可演示的完整指挥环"，候选工作项：

1. **统一状态所有权**（对应 REQ-N-001）：目标、任务、设备和日志由统一工作流或状态仓库管理，UI 不持有可变业务副本。
2. **三块 UI 数据流打通**（对应 REQ-N-002）：态势视图、设备状态、决策建议从同一状态源取数，状态变更同步刷新。
3. **资源指派闭环**（对应 REQ-N-003）：选择目标、指派模拟设备、推进模拟任务，设备和任务状态保持一致。
4. **演示模式与操作日志**（对应 REQ-N-004）：构造可复现的演示脚本，记录选择、指派、状态变化和拒绝操作，UI 文案明确标注"模拟"。
5. **按需定义接入边界**（对应 REQ-N-005）：只有获批功能存在真实调用方时才定义接口，不提前创建空接口和目录。

NEXT 不包含：UXR 完整识别服务、MOS 多方案规划、真实设备控制、数据库持久化、网络通信。这些属于后续阶段，见第 8 节路线图。

`[Q?]` NEXT 是否需要绑定时间窗口（如 4 周）还是按能力项滚动。

## 9. 安全边界

来源：`docs/dev/simulation-policy.md` 与 `AGENTS.md`。

### 9.1 允许

- 使用本地 JSON 或内存对象模拟任务、目标、设备状态、处置方案。
- UI 展示模拟设备在线、电量、位置、工具状态和任务进度。
- 为未来真实接口定义边界清晰的抽象，但不连接真实设备。
- 模拟状态流转与操作日志仅存在于进程内存，重启后重置。
- UI 触发的模拟操作文案必须包含"模拟"字样。

### 9.2 禁止

- 发送真实设备控制命令。
- 执行真实排弹或抢修动作。
- 将模拟数据写入真实数据库或外部系统。
- 在 UI 或文档中把模拟状态描述成真实接入状态。
- 未经用户明确授权接入外部通信链路。
- 提交 `.env`、密钥或凭据文件；`opencode.json` 只能使用环境变量引用 provider key。

### 9.3 命名约定

- 模拟服务使用 `Mock`、`Simulation` 或 `Demo` 前缀后缀。
- 真实接入接口使用 `Interface` 或 `Adapter`，并在文档中说明尚未接入。
