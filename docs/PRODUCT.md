## 1. 产品定义

`UXOMissionControl` 是排弹抢修指挥系统中的指挥席客户端，用于汇集目标、任务和设备信息，支持态势研判、处置决策、资源指派、执行监控与结果反馈。

当前仓库实现的是该系统的指挥席客户端 `UXOMissionControl`，技术栈为 Qt 5 / CMake / C++17 桌面程序。本文件区分三层事实：

- **TARGET**：指挥席客户端的长期目标能力。真实探测设备、AI 服务、排爆设备、数据库与通信平台属于外部系统，本仓库只负责获批的客户端接入、交互和状态呈现边界。
- **CURRENT**：已交付的模拟演示 MVP，仅本地内存数据，无任何真实设备接入。
- **NEXT**：把当前模拟工作流打磨为"可用指挥环演示"的方向草稿，不构成实施承诺。

### 1.1 产品边界

本仓库负责：

- 指挥席桌面客户端的应用生命周期、工作区、交互流程和状态呈现。
- 客户端内的目标、任务、设备与操作日志工作流。
- 本地模拟场景、模拟业务操作和演示数据。
- 只有在功能获批且存在调用方时，定义客户端所需的最小外部接入端口。

本仓库不负责：

- 无人机、传感器、排爆机器人及其固件、控制器和安全执行链。
- AI 模型训练、真实推理基础设施、通信服务器、数据库服务和中心平台。
- 绕过外部安全系统直接执行真实排爆、抢修或设备控制动作。

完整目标系统只作为客户端的运行环境和需求来源，不构成本仓库的直接交付范围。

## 2. 用户角色

来源：SRS 2.4。

| 角色 | 职责 | CURRENT 是否覆盖 |
|------|------|------------------|
| 指挥员 | 任务调度、指令下达、态势研判 | 部分。可查看态势与决策建议，无真实指令下达 |
| 操作员 | 设备操控、现场处置、告警处理 | 部分。仅模拟工作流面板可推进目标状态 |
| 维护员 | 系统配置、故障处理、数据管理 | 未覆盖。`config/` 仅静态文件 |

NEXT 采用单一指挥席用户模式：同一用户完成目标选择、模拟设备指派和模拟任务推进，不实现登录、角色切换或权限控制。上述角色用于描述 TARGET 的职责边界，不代表 NEXT 需要实现多角色系统。

## 3. 端到端指挥环

TARGET 系统的完整闭环（来自 SRS 3.1 至 3.6）：

```
探测采集 -> 目标识别 -> 信息标注 -> 态势融合 -> 决策规划 -> 处置执行 -> 效果评估
   |          |          |          |          |          |          |
 全域多     AI 图像    GIS 标注    三维态势    威胁评估    远程控制    实时反馈
 传感器    多源融合    三维渲染    实时更新    路径规划    排爆机器人
```

CURRENT 实现的闭环只覆盖中间一环的模拟切片：

```
模拟场景加载 -> 目标列表展示 -> 选中目标 -> 状态推进 -> 操作日志追加
   (DemoScenario     (LeftPanel)    (Workflow)   (Detected->      (内存有序
    Provider)                                       Confirmed->      日志)
                                                    Disposing->
                                                    Disposed)
```

NEXT 草稿方向（第 8 节）的目标是把这条模拟切片补成"可演示的完整指挥环"。

## 5. CURRENT 发布范围

### 5.1 范围

- 启动 `UXOMissionControl` 显示标题为"排弹抢修指挥系统 V1.0"的主窗口。
- 加载本地模拟演示场景：1 个目标、1 个任务、2 个模拟设备。
- 主窗口左侧模拟工作流面板可选中目标并推进 `Detected -> Confirmed -> Disposing -> Disposed` 状态。
- 每次状态变更按时间顺序追加到内存操作日志。
- 决策建议面板与设备状态面板只读展示模拟数据，不发起真实控制。
- 4 个 CTest 用例覆盖启动可见性、场景提供器、工作流功能与 UI 行为。

### 5.2 非目标

- 不接真实探测设备、无人机、排爆机器人。
- 不发送任何真实控制指令。
- 不实现 AI 识别、多源融合、路径规划、殉爆计算。
- 不写入真实数据库，不持久化，不接入外部通信链路。
- 不实现用户认证、角色切换、权限、加密、日志审计的真实逻辑（`Application::initialize()` 中相关初始化为占位返回成功）。
- 不修复已知 P2 问题：1280×720 窗口最小尺寸下 `DecisionSuggestionPanel` 底部约 5px 溢出。

### 5.3 验证

最近一次构建与测试在 `uxo-dev` 环境下完成，结果：构建通过，CTest 4/4 通过。命令见 `docs/dev/build-and-run.md`。

## 6. 需求表（稳定 ID）

需求 ID 格式为 `REQ-<DOMAIN>-<NNN>`。ID 只表达需求所属业务域，不表达 CURRENT/NEXT/TARGET 状态。

当前允许使用的域前缀：

| 前缀 | 适用范围 |
|------|----------|
| `APP` | 应用生命周期、会话、配置与权限边界 |
| `SCN` | 本地场景、模拟数据与可复现演示输入 |
| `CMD` | 目标、任务、设备、决策、执行与日志工作流 |
| `UI` | 导航、页面、展示与交互反馈 |
| `EXT` | 外部通信、存储、设备和服务的客户端接入边界 |
| `UXR` / `MOS` | 对应功能获批后使用的专属前缀；草案沿用现有设计 ID，不提前扩展实现需求 |

编号规则：

1. 每个域从 `001` 独立递增；已分配编号永久保留，不重排、不复用。
2. 状态变化只修改“状态”列，需求 ID 不变。
3. 需求拆分时保留原 ID 并标记“已替代”，新需求获得新 ID；合并时同理记录来源，不改旧 ID。
4. 旧 SRS、SDD 和研究资料中的条目只有被本文件采用后才分配当前基线 ID，避免为未进入路线的内容制造维护负担。
5. 新增域前缀必须先修改本节；单个功能不得自行创造近义前缀。

## 7. NEXT 目标：完整模拟指挥环

本节方向已由用户确认；具体需求、交互和架构仍需完成四份核心文档评审，评审完成前不构成代码实施授权。

NEXT 要把当前“选择目标并推进状态”的模拟切片扩展为可操作、可观察、可验证的本地模拟指挥闭环：

```
加载可复现场景
  -> 查看并比较模拟目标
  -> 选择处置目标
  -> 查看模拟决策依据
  -> 指派可用模拟设备
  -> 推进模拟任务执行
  -> 目标、任务、设备和态势同步反馈
  -> 完成处置并形成有序操作日志
```

工作项：

1. **统一状态所有权**（对应 REQ-CMD-002）：目标、任务、设备和日志由统一工作流或状态仓库管理，UI 不持有可变业务副本。
2. **三块 UI 数据流打通**（对应 REQ-UI-004）：态势视图、设备状态、决策建议从同一状态源取数，状态变更同步刷新。
3. **资源指派闭环**（对应 REQ-CMD-003）：选择目标、指派模拟设备、推进模拟任务，设备和任务状态保持一致。
4. **演示模式与操作日志**（对应 REQ-SCN-002）：构造可复现的演示脚本，记录选择、指派、状态变化和拒绝操作，UI 文案明确标注"模拟"。
5. **按需定义接入边界**（对应 REQ-EXT-003）：只有获批功能存在真实调用方时才定义接口，不提前创建空接口和目录。

NEXT 不包含：UXR 完整识别服务、MOS 多方案规划、真实设备控制、数据库持久化、网络通信。这些属于后续阶段，见第 8 节路线图。

### 7.1 NEXT 验收结果

- 同一场景中的目标、任务、设备和日志只有一个权威状态来源。
- 单一指挥席用户可以在一个客户端会话内完成整条模拟流程，不依赖角色切换或多人交接。
- 操作员可以选择目标并指派处于可用状态的模拟设备。
- 指派后任务进入执行流程，设备状态、目标状态和相关 UI 同步变化。
- 完成任务后目标进入已完成状态，设备恢复可用状态。
- 重复指派、无目标指派、向不可用设备指派等非法操作被拒绝，并写入模拟操作日志。
- 态势、设备、决策和日志界面显示同一业务事实，不依赖手工刷新不同副本。
- 所有动作只作用于本地内存模拟状态，不发送外部命令，不写入外部系统。

## 9. 安全边界（强制）

来源：`docs/dev/simulation-policy.md` 与 `AGENTS.md`。本节“禁止”项均为强制边界，不是建议性规范。

### 9.1 允许

- 使用本地 JSON 或内存对象模拟任务、目标、设备状态、处置方案。
- UI 展示模拟设备在线、电量、位置、工具状态和任务进度。
- 为未来真实接口定义边界清晰的抽象，但不连接真实设备。
- 模拟状态流转与操作日志仅存在于进程内存，重启后重置。
- UI 触发的模拟操作文案必须包含"模拟"字样。

### 9.2 禁止

- 发送真实设备控制命令。
- 执行真实排弹或抢修动作。
- 将模拟数据写入真实数据库或外部系统。
- 在 UI 或文档中把模拟状态描述成真实接入状态。
- 未经用户明确授权接入外部通信链路。
- 提交 `.env`、密钥或凭据文件；`opencode.json` 只能使用环境变量引用 provider key。

### 9.3 命名约定

- 模拟服务使用 `Mock`、`Simulation` 或 `Demo` 前缀后缀。
- 真实接入接口使用 `Interface` 或 `Adapter`，并在文档中说明尚未接入。

## 11. 本轮已确认决策

- 产品边界是本仓库交付的指挥席客户端；完整目标系统是外部环境和需求来源。
- NEXT 以完整本地模拟指挥环为验收目标，UXR/MOS 不进入本轮 NEXT。
- NEXT 使用单一指挥席用户，不实现登录、角色切换和权限控制。
- 需求 ID 按稳定业务域编号，状态变化不改 ID，旧资料只在被采用后分配当前基线 ID。
- NEXT 不写没有依据的固定工期，按能力和验收结果推进。
- 旧 SRS 的系统级性能数字暂不进入当前客户端基线。
- 模拟与真实接入安全禁令作为强制边界执行。
