## 1. 范围与非目标

### 1.1 范围

- 本地合成模拟跑道几何、损毁点模型和模拟场景 fixture；所有坐标、距离、半径均为本地合成 fixture 几何参数，不对应真实跑道、真实坐标或真实工程量。
- 纯本地最大轴对齐空矩形计算、递进方案计算和模拟修复估算，结果只是模拟派生值，不表达真实跑道安全、工程或作业结论。
- 决策页中的 MOS 结果展示、参数配置和模拟场景生成入口，全部以合成本地模拟数据为基础。
- 遵循本文件 §2、§3 定义的功能本地 Draft 会话边界。

### 1.2 非目标

- 不接入真实传感器、真实 AI、真实坐标转换或外部通信。
- 不发送真实设备命令，不执行真实排弹、抢修或起降安全决策。
- 不在本草稿中确定具体 C++ 类、接口签名、Repository/Store、事件总线、数据库、运行时持久化、外部集成或部署方式。
- 不引入本文件 §2 功能本地会话边界之外的独立权威状态、运行时持久化或回灌通道。
- 不把浏览器 JSON 导出当作运行时持久化、运行时输入来源或已批准的外部集成通道。
- 不赋予任何安全系数、standoff 距离、当量、修复时间、跑道尺寸或难度值以真实安全、工程、作业或执行含义。

## 2. 数据与状态边界

本节定义 MOS 特有的功能本地 Draft 会话边界提案，由本文评审，不依赖核心基线中的特定章节。概念上只有一个应用拥有的内存模拟会话作为权威来源，统一持有已接受的 fixture 输入、参数与选择、派生 MOS 结果，以及一份进程内内存操作日志；UI 只保存选中索引、折叠状态等展示状态。

1. `RunwayModel` 使用配置的本地合成米制 fixture 几何；默认跑道长度与宽度为 3000×50m，默认损毁分布核心区宽 500m。可配置范围与搜索边界以 [`../features/mos-planning.md`](../features/mos-planning.md) §4 `P0 技术输入包络` 和 `算法正确性契约` 为准。这些只是合成 fixture 几何约束，不代表真实跑道尺寸或真实坐标。
2. `DamagePoint` 只表示本地合成模拟损毁数据，包含类型、影响半径、修复状态和模拟来源标识；影响半径是合成 fixture 参数，不是真实损毁半径或安全半径。
3. `MOSPlanParams` 只承载本地合成规划参数；默认值是示例值，安全系数、standoff 距离、当量、修复时间、难度等字段均为原型/合成字段，必须在 UI 中明确标注待业务确认，且不能支持真实安全或作业决策。
4. `MOSPlanResult` 只表示模拟派生结果，不能被描述为真实跑道状态或真实工程指令。
5. fixture 提供器只负责构造输入；纯 MOS 计算/估算器只负责返回派生结果并回交会话；两者都不拥有、也不直接修改权威业务状态。
6. 浏览器 JSON 导出属于设计期样例数据，与本会话边界解耦，不是运行时持久化，也不是已批准的运行时输入或外部集成通道；它不得回灌权威会话状态或外部系统。
7. 所有几何、距离、修复时间、难度等数值均为合成模拟参数或派生结果，无真实跑道安全、工程、作业或执行含义。

## 3. 规划流程

本节定义 MOS 特有的功能本地 Draft 规范流程提案，由本文评审，不依赖核心基线中的特定章节。流程为：UI 请求 -> 应用校验 -> 纯 fixture 构造/计算 -> 会话状态与中心内存日志原子提交 -> 一次变更通知 -> UI 回查与渲染。

```text
决策页 UI 发起请求（参数/选择/触发）
  -> 应用层校验输入与权限
  -> 模拟跑道/损毁 fixture 构造（纯构造，不修改权威状态）
  -> MOS-002 轴对齐空矩形计算 / MOS-003 递进方案组合 / MOS-005 模拟修复时间与难度估算（纯计算，仅返回派生值）
  -> 会话原子提交：接受结果更新会话状态，并在进程内内存日志追加一条记录
  -> 发送一次变更通知
  -> 决策页回查权威会话状态并渲染当前模拟方案
```

合法请求路径：校验与计算均成功时，按上述流程原子提交会话状态与一条记录，发一次通知，UI 回查并渲染。合法但无可行矩形的结果按 `valid=false` 接受（见 [`../features/mos-planning.md`](../features/mos-planning.md) §4 算法正确性契约的 No-solution 项），视为一条被接受的命令并写一条接受记录，不是拒绝。

被拒绝的请求路径：应用校验或计算失败时，返回拒绝原因，会话业务状态不变，仅在内存日志原子追加一条拒绝记录，UI 仍回查并渲染当前权威模拟状态。

P0 算法目标、搜索边界、离散化、碰撞、无解、总排序、递进档位不变量与复杂度目标由 [`../features/mos-planning.md`](../features/mos-planning.md) §4 `算法正确性契约` 和 `P0 技术输入包络` 统一拥有。本文只约束纯计算职责、状态所有权与调用流程，不复制算法正确性规则。

## 4. UI 与核心模块关系

- UI 只保存选中索引、折叠状态等展示状态，不保存可独立修改的业务状态；权威业务状态只存在于本文件 §2 定义的内存模拟会话。
- 核心算法和数据边界应与 QWidget/QPainter 展示解耦；fixture 提供器与纯计算只构造输入或返回派生值，不直接修改会话状态。
- UI 只消费模拟派生结果并显示模拟、空、错误和待确认状态；状态变化后只发一次统一通知，UI 回查权威会话状态。
- 决策页逐控件行为由 [`../ui/pages/decision.md`](../ui/pages/decision.md) 维护；本文件不复制控件布局。
- UI 评审通过后，具体状态归属和信号链路才能进入实现计划。
