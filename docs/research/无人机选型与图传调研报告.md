## 1. 核心结论与推荐路线

### 1.1 推荐策略：三阶段混合方案

```
第一阶段：仿真验证（PX4 SITL + Gazebo）
    → 零硬件成本，验证飞控逻辑、图像处理算法管线
    → 耗时：1-2个月

第二阶段：开发级真机（DJI Matrice 4T + DJI SDK 生态）
    → 利用成熟的 SDK 体系快速打通图传→解码→AI分析的完整链路
    → 预算：¥40,000-45,000（旗舰套装）

第三阶段（可选）：开源自研平台（Pixhawk + 配套计算机 + 第三方双光吊舱）
    → 适合需要完全自主可控、深度定制飞控的场景
    → 预算：¥20,000-50,000（取决于配置）
```

### 1.2 为什么不推荐纯商品级消费无人机

- DJI Mavic 系列消费级不提供 SDK 接口
- 商品级产品图传加密、不支持原始视频流提取
- 飞行控制黑盒化，无法注入自主航线规划逻辑

### 2.3 图传接收方式（DJI Cloud API 路径）

这是**最简单且最完整的接入方式**，适合排弹指挥系统：

```bash
# 架构：无人机 → DJI Pilot 2 (内置MQTT) → 三方云平台 → 指挥席客户端

# 1. 注册 DJI Developer 账号，创建应用获取 AppID/Key
# 2. 在 DJI Pilot 2 中配置上云 API 地址（MQTT Broker）
# 3. 指挥系统后台订阅以下 MQTT Topic：

# 无人机实时状态
thing/product/{sn}/osd    # 姿态/位置/电量/GPS

# 实时视频流（获取直播URL后拉流）
thing/product/{sn}/live   # RTMP 直播地址

# 媒体文件上传通知
thing/product/{sn}/media  # 照片/视频上传完成通知

# 4. 视频流处理管线：
MQTT获取直播URL → FFmpeg/GStreamer拉RTMP流 →
H.264解码 → OpenCV Mat帧 → Qt渲染/送入AI推理
```

**代码示例（C++/Qt集成）**：

```cpp
// 基于 MQTT 接收无人机状态 + FFmpeg 解码图传
// 伪代码示意

// 1. MQTT Client 连接（可以用 mosquitto/QMqttClient）
connectToDJICloudAPI("mqtts://your-server:8883", appId, appKey);

// 2. 订阅 OSD 数据（1Hz推送）
subscribe("thing/product/*/osd");
// 回调解析：latitude, longitude, altitude, attitude, battery, ...

// 3. 获取直播流
// Cloud API 返回 RTMP URL
// 用 FFmpeg 拉流解码：
// ffmpeg -i rtmp://live-server/drone-001 -f rawvideo -pix_fmt bgr24 pipe:1
// → Qt 中逐帧渲染到 QLabel/QOpenGLWidget
```

### 3.3 图传接收流程（开源方案）

```bash
# 方案1：Herelink HDMI → 地面端 Android → WiFi共享 → PC拉流
# 地面端QGC通过WiFi将视频+遥测共享到PC
# PC端QGC订阅 MAVLink UDP 14550 端口

# 方案2：SIYI RTSP → PC端直接拉流
gst-launch-1.0 rtspsrc location=rtsp://192.168.144.108:8554/stream latency=0 \
  ! rtph264depay ! avdec_h264 ! videoconvert ! appsink

# 方案3：FFmpeg拉RTSP流并转推本地，供Qt应用消费
ffmpeg -rtsp_transport tcp \
  -i rtsp://192.168.144.108:554/stream \
  -c:v copy -f rawvideo -pix_fmt bgr24 \
  tcp://127.0.0.1:9999
```

### 4.2 仿真环境搭建（Ubuntu 22.04）

```bash
# 1. 安装 PX4 SITL
git clone https://github.com/PX4/PX4-Autopilot.git
cd PX4-Autopilot
make px4_sitl gazebo-classic

# 2. 启动四旋翼仿真
make px4_sitl gazebo-classic_iris

# 3. 安装 ROS2 + mavros（用于offboard控制）
sudo apt install ros-humble-mavros ros-humble-mavros-extras

# 4. 启动 MAVROS 桥接
ros2 launch mavros px4.launch.py fcu_url:="udp://:14540@127.0.0.1:14557"

# 5. 订阅无人机状态
ros2 topic echo /mavros/local_position/pose
ros2 topic echo /mavros/imu/data

# 6. 模拟相机视频流
# Gazebo 中无人机模型自带 camera 插件 → 发布到 ROS topic
ros2 run image_view image_view image:=/iris/camera/image_raw

# 7. 注入自定义 AI 检测管线
# 订阅 camera topic → OpenCV DNN/YOLO → 发布检测结果
```

### 4.3 仿真环境的优势

| 能力 | 支持情况 |
|------|----------|
| 飞控逻辑验证（起飞/降落/航线/返航） | ✅ 完整支持 |
| Offboard 模式控制（ROS2/mavros） | ✅ 完整支持 |
| 可见光图像模拟 | ✅ Gazebo 相机插件 |
| 红外图像模拟 | ⚠️ Gazebo 热传感器插件（功能有限） |
| 真实图传延迟/丢包模拟 | ❌ 需要额外网络模拟工具 |
| 多无人机编队仿真 | ✅ Gazebo 多机 |
| 硬件在环 (HITL) | ✅ 真飞控板 + Gazebo |
| 故障注入测试 | ✅ 注入传感器故障/GPS丢失 |

### 4.4 仿真方案评价

| 优势 | 劣势 |
|------|------|
| 零硬件成本 | 红外相机仿真保真度有限 |
| 安全——摔机零成本 | 无法验证实际图传链路延迟 |
| PX4 → 真机迁移路径成熟 | 视觉SLAM/避障仿真与真实环境差距大 |
| 可重复、可自动化测试 | 需要团队掌握 PX4/ROS2/Gazebo |
| 支持 CI/CD 集成 | 大规模仿真对电脑性能要求高 |

## 6. 图传信号接收与处理技术方案

### 6.1 主流图传协议对比

| 协议 | 延迟 | 带宽 | 适用场景 | 开发难度 |
|------|------|------|----------|----------|
| **RTSP** (TCP) | 200-500ms | 中 | 标准IP摄像头拉流 | ★☆☆ |
| **RTMP** | 1-3s | 高 | 直播推流 | ★☆☆ |
| **SRT** | 100-300ms | 高 | 低延迟公网传输 | ★★☆ |
| **DJI O4 私有协议** | 100-150ms | 高 | DJI 封闭生态 | ★★★ |
| **MAVLink 视频流** | - | 低 | PX4/ArduPilot | ★★☆ |
| **GB28181** | 500ms+ | 中 | 安防国标 | ★★★ |

### 6.2 推荐解码管线

```
无人机端：
  相机传感器 → H.264/H.265编码 → RTSP/RTMP推流/私有图传

地面接收（指挥席 Qt/C++ 客户端）：
  方案A（推荐—DJI Cloud API 路径）：
    MQTT获取RTMP URL → FFmpeg libavcodec 拉流解码
    → AVFrame → QImage → QPixmap → QLabel/QGraphicsView 渲染
    → 同时送入 OpenCV cv::Mat → DNN 推理 → 检测框叠加

  方案B（开源 RTSP 路径）：
    GStreamer rtspsrc → decodebin → appsink
    → 回调获取 GstBuffer → QImage 渲染

  方案C（FFmpeg 命令行管道）：
    ffmpeg -i rtsp://... -f rawvideo pipe:1 | Qt应用读取stdin逐帧解析
```

### 6.3 红外图像处理

- **DJI Thermal SDK**：R-JPEG → 温度矩阵（-20°C~550°C），C API，Windows/Linux
- **FLIR SDK**（如使用第三方热像仪）：14-bit 原始辐射数据 → 温度换算
- **通用方案**：伪彩色映射 + 自动增益 + 热斑检测（OpenCV + 自定义算法）

### 6.4 与 Qt/C++ 指挥席集成

```cpp
// 参考架构：图传模块在 SDD 中位于"硬件抽象层 → 无人机控制"
// 现有代码结构：include/ + src/ 中扩展 VideoStream 模块

// 新增模块建议：
include/Core/VideoStream/VideoReceiver.h      // 统一视频流接收接口
include/Core/VideoStream/RTSPReceiver.h       // RTSP 拉流实现
include/Core/VideoStream/MAVLinkVideo.h       // MAVLink 视频数据解析
include/Core/VideoStream/ThermalProcessor.h   // 红外温度矩阵处理
src/Core/VideoStream/                          // 对应实现

// 接口设计：
class IVideoReceiver {
public:
    virtual bool connect(const QString& url) = 0;
    virtual QImage getFrame() = 0;          // 获取单帧用于渲染
    virtual cv::Mat getFrameMat() = 0;      // 获取单帧用于AI推理
    virtual void disconnect() = 0;
signals:
    void frameReady(const QImage& frame);     // 新帧到达信号
    void streamStatus(const QString& status); // 图传状态
};
```
