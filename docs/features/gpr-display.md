# 探地雷达样例数据展示与目标模拟演示

状态：Approved
关联产品需求：REQ-012（requirements/REQ-012.md）
关联版本：待确认

> 本文档与 REQ-012 同步评审。样例数据格式预研已完成（证据：`.omo/evidence/gpr-research/`，2026-10-11），结论已回填第 5.4 节与第 9 节，其余章节为设计基线。

## 1. 问题与目标

### 1.1 问题

- 当前客户端只有无人机视频 AI 检测（REQ-009 + `DetectionEngine`）一种探测来源；探地雷达（GPR）是埋地未爆弹探测的核心传感器，客户端完全没有 GPR 数据接入、解析与展示能力。
- 当前无实时雷达数据获取能力，仅有一段样例数据可用于演示：泰安测试 2025-11-13，MALA 格式（`.rad` 文本头 + `.rd3` int16 二进制 + `.cor` RTK 轨迹），H/L 两组采集 × 16 组收发通道，共约 235MB（预研证实 H/L 为近重复记录，见 §5.4）。
- 样例数据格式理解与阈值检测可行性已经独立 Python 预研验证（证据回填 §5.4）：三种格式全部可独立解析；阈值检测存在漏检与过检两类失效，仅适合作候选标记，人工复核必需。

### 1.2 目标

- 以纯 C++/Qt 实现 MALA GPR 数据解析层（`.rad`/`.rd3`/`.cor`），不引入第三方 GPR 库。
- 新增"雷达"页：B-Scan 伪彩剖面展示、频段/通道切换、回放控制、当前道 RTK 位置与时间戳显示。
- 简单阈值自动检测疑似目标，经人工校验（确认/误报）后注入统一目标列表并在 2D 战术地图落点，与探测页"AI 分析 + 人工二次校验"模式对齐。
- 与视频 AI 检测确认的目标完全同构：同一 `SimulationWorkflow` 四状态机、同一目标表、同一地图标点体系。

### 1.3 与 SRS 四阶段的关系

本功能只做**探测阶段**的 GPR 传感器数据展示与目标发现演示。识别/规划/排弹属于后续独立功能，各自走审批流程，不在本功能范围内。

## 2. 范围与非目标

### 2.1 范围

- 新建 `GPR` 静态库（`src/GPR/` + `include/GPR/`）：`.rad` 头解析、`.rd3` B-Scan 数据懒加载读取、`.cor` RTK 轨迹解析与道对齐插值、数据集清单扫描（H/L × 16 通道文件组聚合）、简单阈值检测器。仅依赖 `Qt5::Core`，不含 Widgets 代码，解析与检测逻辑可纯数据测试。
- 新增雷达页（`QStackedWidget` index 3）：`GprBScanWidget` 剖面渲染 + 回放控制条 + 疑似目标列表面板 + 顶部工具栏（频段/通道/增益）。
- 数据经外部路径配置加载（不入库），参考 `DETECTION_ASSETS_DIR`/`MEDIA_ASSETS_DIR` 的编译期宏 + 运行期回退模式。
- 人工校验闭环：确认目标经 RTK 插值获得经纬度，注入统一目标列表（态势页目标表可见）、2D 战术地图红点（标注 [模拟]）、操作日志；标记误报从列表移除并记日志。
- 数据不可用降级态：路径未配置或文件缺失时雷达页显示明确空/错误态，不影响其他页面。
- 测试：GPR 解析层单元测试（合成 fixture + 可选真实数据 smoke）、雷达页 UI 契约测试（离屏）、三视口截图（复用 REQ-011 门禁设施）。

### 2.2 非目标

- **不接真实雷达设备**：不做实时数据流、设备控制或通信协议；仅本地样例数据回放。
- **不做视频-GPR 时间同步**：样例 GPR 数据与演示视频非同场景采集，两者回放相互独立。
- **不做双曲线形态识别或 AI 分类**：阈值检测只找高反射聚集区，不识别 UXO 类型；真实识别算法属后续功能。
- **不做 3D GPR 体数据渲染**：仅单通道 2D B-Scan；多通道融合/层叠/体渲染属后续设计。
- **不做通道横向偏移精确校正**：MVP 以 RTK 阵列车位置近似各通道位置（阵列横向约 1-2m，演示精度足够）；精确通道几何属后续。
- **不改探测页（`DetectionView`）现有行为**：雷达页独立成页，与探测页互不干扰。
- **不做数据入库**：235MB 样例数据经外部路径引用；测试用合成 fixture，真实数据 smoke 测试在无数据环境下自动跳过。
- **不做 REQ-001~006 统一会话重构**：在现有 MainWindow 手工同步模式上增量改造，与 REQ-009 做法一致。
- **不做识别/规划/排弹阶段**（各自独立功能）。

## 3. 用户流程

### 3.1 主流程

1. 启动客户端，导航栏出现"雷达"项（index 3）。
2. 点击进入雷达页：数据路径有效时，加载数据集清单，默认选中 H 组第一通道，B-Scan 伪彩剖面渲染显示；数据路径无效时显示降级态（明确提示 + 配置说明），不影响其他页面。
3. 用户切换数据组（H/L）或通道（16 组 T/R 对），B-Scan 更新。
4. 用户调整增益/对比度/缩放，查看剖面细节。
5. 点击 [播放]：回放游标沿测线移动，底部状态实时显示当前道索引、RTK 经纬度、时间戳；可暂停、变速（1×/2×/4×）、拖拽进度条定位。
6. 阈值检测结果以标记框叠加在 B-Scan 对应位置（疑似双曲线/高反射区），右栏疑似目标列表同步展示。
7. 用户点击列表中疑似目标 → B-Scan 视图跳转定位到该道，标记高亮。
8. 用户点击 [确认目标] → 目标经 RTK 插值获得经纬度 → 注入统一目标列表（态势页目标表插行）→ 2D 战术地图出现红点（标注 [模拟]）→ 操作日志追加；该候选同时从疑似列表移除（防重复注入，见 §5.3 实现补充）。
9. 用户点击 [标记误报] → 疑似目标从列表移除 → 操作日志追加。
10. 切换到态势页：目标表可见 GPR 来源目标（来源标注 [GPR自动检测][模拟]），地图红点与目标表双向高亮，可走现有模拟确认/处置/完成流程。

### 3.2 降级流程

1. 数据路径未配置或文件缺失：雷达页中心区显示空/错误态说明（非崩溃、非空白），其余页面功能不受影响。
2. 数据集部分通道文件缺失：缺失通道在切换器中禁用并标注，其余通道正常使用。

## 5. 架构增量

### 5.1 新增构建目标

| 构建目标 | 源码位置 | 责任 | 直接项目依赖 |
|----------|----------|------|--------------|
| `GPR`（静态库） | `src/GPR/`、`include/GPR/` | MALA 格式解析、数据集清单、RTK 轨迹、阈值检测 | 无项目依赖（仅链接 `Qt5::Core`） |

依赖方向：`MainWindow` → `GPR`。`GPR` 不依赖 `Core`/`MainWindow`/`Detection`，不含 Widgets 代码，解析与检测逻辑以纯数据测试覆盖。该归属与 TARGET 架构一致：GPR 库未来归 `Simulation`（本地数据源）或 `Integration`（真实接入适配）的过渡组件，当前只接本地样例文件。

### 5.2 GPR 库组件

| 组件 | 类型 | 职责 |
|------|------|------|
| `GprRadarHeader` | 值类型 | `.rad` 键值对解析：采样数、时窗、道间距等采集参数（`ANTENNAS` 字段与实测主频矛盾，不作频率依据，见 §5.4） |
| `GprBScanData` | 类 | `.rd3` 懒加载读取：道 × 样本 int16 访问，按需读盘，不一次加载 235MB；提供逐通道 t0（first-break）校正，校正后才换算深度 |
| `GprTrack` | 类 | `.cor` RTK 轨迹解析：道号 1:1 对齐（预研已断言）→ 经纬度/时间戳映射；载入时重平滑（样条/卡尔曼，实现阶段选型）；时间戳统一 UTC 存储、本地显示 |
| `GprDataset` | 类 | 数据集目录扫描：识别 H/L 两组、16 组通道文件组，聚合为"一次采集"，报告缺失通道 |
| `GprThresholdDetector` | 类 | 阈值候选检测（预研验证管线，见 §5.4）：去直流 → t0 截取 → 横向背景去除 → 包络 → 深度白化 → 逐通道 P99.5 自适应 → 形态学聚集 → 疑似目标列表（道索引、样本索引、深度、幅度）；仅作候选标记，人工复核必需 |

### 5.3 MainWindow 增量组件

| 组件 | 类型 | 职责 |
|------|------|------|
| `GprView` | 新建（QWidget） | 雷达页主视图，装配工具栏、`GprBScanWidget`、回放控制条、疑似目标面板；经 `QStackedWidget` index 3 路由 |
| `GprBScanWidget` | 新建（QWidget） | B-Scan 伪彩渲染（QImage 映射）、增益/对比度/缩放、回放游标、疑似目标标记叠加 |
| `GprSuspectPanel` | 新建（QWidget） | 疑似目标列表（ID/道索引/深度/幅度，标注 [模拟][GPR自动检测]）+ [确认目标]/[标记误报] 按钮 |
| 回放控制条 | `GprView` 内部 | 播放/暂停/速度/进度条/当前道经纬度时间戳显示 |

状态所有权：疑似目标列表与回放位置属 `GprView` 展示态；确认后的目标走 `SimulationWorkflow` 权威状态机（与 REQ-009 一致，MainWindow 手工同步，不做 REQ-001 全量重构）。

实现补充（阶段 3，2026-10-12）：确认/误报按钮先同步发出意图信号（携带候选 ID），再由 `GprView` 本地移除候选——MainWindow 槽内仍可经 `GprView::suspects()` 读取候选内容，处置完成即离开复核队列、防重复注入；确认时若候选道无有效 RTK 定位则不注入目标体系（仅状态栏告警），避免无坐标红点；误报不触发工作流状态转换（疑似候选从未进入目标体系），仅记日志。

### 5.4 数据格式预研结论

证据：`.omo/evidence/gpr-research/REPORT.md` + 9 张经人工核验的 PNG（2026-10-11，纯 Python/numpy/scipy/matplotlib 独立解析，不依赖厂商 SDK，数据源只读）。以下结论作为本设计参数依据。

**格式（已验证）**

- `.rad`：`SAMPLES=512`、`TIMEWINDOW=110` ns、`DX=0.02` m；采样间隔 ≈0.2148 ns；v=0.1 m/ns（两程时间）全时窗深度约 5.5 m。`ANTENNAS:800` 与实测主频 216–222 MHz 矛盾，**不作为频率或显示参数**。
- `.rd3`：32 个文件 = 2 组（H/L）× 16 通道（T1R1…T8R9）；int16 小端，7297 道 × 512 样本，全部通过尺寸断言（无截断/错位）。
- `.cor`：7297 行 × 14 字段；道号字段与 `.rd3` 道 **1:1 对齐**（代码断言通过），可直接作逐道位置源；纬度/经度/日期/时间（微秒）字段已解码，其余 8 字段未解码（不影响本功能）；记录号存在少量跳变但不影响道号对齐；点率 ≈81 点/秒。`.cor` 时间与文件名时间戳相差约 8 小时（时区差异），**Qt 端统一 UTC 存储、本地显示**。
- 通道时延：各通道 first-break 样本不同（H 组 47–59 / L 组 46–59，通道间最大差 ≈13 样本 ≈2.8 ns），**显示与检测前必须逐通道 t0 校正**，校正后再换算深度。

**H/L 关系**

- 同通道 H/L 波形相关系数 0.953–0.981，谱心频率完全相同（216–222 MHz）；两组检测统计亦相近（H 780 命中 / L 796 命中）→ H/L 为**近重复记录**，"双频带"未获数据支持。
- 设计含义：默认显示单组（H），另一组作冗余备份与对照切换；不按"双频带"设计交互。

**RTK 定位**

- 1:1 道对齐可直接使用。
- 原始轨迹相对行进轴横向抖动 std 1.43 m；σ=3 m 高斯平滑不足（平滑路径仍比端点弦长 128.23 m 长 25%）→ **载入时需更强平滑（样条/卡尔曼/更宽核，实现阶段选型）后再地理配准**。
- 里程计（7297×0.02=145.94 m）比 RTK 沿程跨度（128.19 m）超估约 14% → **RTK 为主定位源，里程计仅作间隙插值与备份**。
- 轨迹呈弓形（最大弓高 +4.34 m），单趟数据无法区分真实弯道与 GPS 缓漂；地图叠加时需提示，正式部署需多趟标定。

**阈值检测（可行性结论：仅候选标记）**

- 已验证管线：去直流 → t0 截取 → 横向背景去除（101 道滑窗）→ 包络 → 深度白化（增益上限 10）→ **逐通道** P99.5 阈值 → 15×9 膨胀 → ≥15 px 连通域；检测窗 t≤91.3 ns（深度约 4.6 m）。命中统计：H 组 780 / L 组 796。
- 各通道阈值差异大（668–2086），跨通道统一阈值无意义，**必须逐通道自适应**。
- 两类失效均已证实（fp_analysis.png）：
  - 弱事件漏检：98.6–99.6 m 处 AGC 视图清晰事件，包络峰值仅为全局阈值的 0.35 倍，局部窗阈值同样漏检 → 纯阈值自动检测不可靠；
  - 非点目标过检：102 m 处竖向相干条带（层界面/多次波类特征），全 16 通道同时触发 ≠ 目标 → **跨通道一致性不作目标判据**。
- 全数据未观察到清晰双曲线绕射形态 → 双曲线拟合无可验证对象（维持 §2.2 非目标）。
- **结论：阈值检测只作候选标记；AGC/时变增益显示 + 人工复核（确认/排除）为必需环节**——与本设计人工校验闭环一致。

**显示参数建议（预研实测有效）**

- 增益：AGC（时变增益）为默认视图，另提供固定增益与未增益原始视图切换。
- 色标与映射：对称 diverging 色标（seismic 类）；P99.8 截幅 + γ=0.8 显示映射。


### 6.3 状态规则

- **正常态**：数据加载成功，B-Scan 可见，回放可用。
- **加载态**：数据集扫描/大文件读取期间显示加载指示，不阻塞窗口。
- **空态（降级）**：数据路径未配置或目录不存在 → 中心区明确提示 + 配置说明文字；回放控件禁用。
- **错误态**：单通道文件损坏/格式不符 → 该通道在切换器中禁用并标注，其余通道可用。
- **禁用态**：播放到底、无检测结果时对应按钮禁用。

### 6.4 通用约束

- 所有 GPR 展示数据标注"模拟"或"演示"；疑似目标列表标注 [GPR自动检测]。
- 状态颜色不作为唯一信息，同时提供文字（沿用 `UI.md` §8）。
- 三视口适配：1280×720 / 1920×1080 / 3840×2160 截图证据，复用 REQ-011 门禁设施。

## 附录 A. GPR 背景知识与术语（非雷达专业读者向）

> 本附录是对正文的通俗解释层：设计契约以 §5.2 为准，预研事实以 §5.4 为准，本附录不新增任何设计决策；两者冲突时以正文为准。

### A.1 GPR 是什么

**GPR（Ground Penetrating Radar，探地雷达）**：一副贴着地面拖着走的天线，边走边向地下发射电磁脉冲；脉冲遇到埋藏的金属、空洞、未爆弹等与土壤电磁性质不同的物体时产生反射回波，被接收天线记录。它是埋地未爆弹探测的核心传感器——无人机视频只能看地表，GPR 能"看"地下。本功能做的是把这套设备采集的样例数据读进客户端、画成图、圈出可疑位置，供人工复核。

### A.2 从回波到图像

- 天线每前进一小段距离打一次脉冲，收到的一串回波称为**一道（trace）**。样例数据每道 512 个**样本（sample）**，按时间先后排列；回波越晚到达，反射源埋得越深。
- 沿测线把几千道并排放在一起，就得到 **B 扫描（B-Scan）**：横轴 = 地面位置（道号），纵轴 = 深度，亮度 = 回波强弱。埋藏的点状物体在 B 扫描上呈现**双曲线**形亮斑——这是肉眼识别目标的经典形态（本批样例数据中未观察到清晰双曲线，见 §5.4）。
- 时间换算深度用**两程时间**公式：`深度 = 波速 × 时间 / 2`（脉冲要走"下去+回来"两段路）。取典型土壤波速 v≈0.1 m/ns，样例 110 ns 时窗对应约 5.5 m 深。
- 每道信号的"时间零点"不是第 0 个样本，而是**初至（first break，t0）**——地表直达波到达的位置。各通道 t0 不同（实测 46–59 样本，最大差约 2.8 ns），**显示与检测前必须逐通道校正**，否则深度全部算错。

### A.3 术语表

| 术语 | 含义 |
|------|------|
| 道（trace） | 一个采集位置的一维回波信号；样例数据每文件 7297 道 |
| 样本（sample） | 一道之内按时间排列的采样点；样例数据每道 512 个，int16 |
| B 扫描（B-Scan） | 多道并排组成的二维剖面图（位置 × 深度） |
| 双曲线绕射 | 点状埋藏物在 B 扫描上的典型双曲线形亮斑 |
| 初至 / first break（t0） | 地表直达波位置，深度换算的零点，需逐通道估计 |
| 时窗（time window） | 每道记录的时长，样例 110 ns（≈5.5 m 深） |
| 道间距（DX） | 相邻道的地面间距，样例 0.02 m；7297 道 × 0.02 m ≈ 146 m 测线 |
| 通道（channel）/ 收发对（TnRm） | 阵列雷达的收发天线组合：8 发射 × 9 接收中实际使用 16 对（T1R1、T1R2、T2R2…T8R9），每对产生一个独立数据文件 |
| H/L 组 | 设备的两组采集；预研证实二者波形相关系数 0.953–0.981、谱心完全相同，为**近重复记录**而非双频带（§5.4），默认显示 H 组 |
| `.rad` / `.rd3` / `.cor` | MALA（瑞典雷达厂商）文件格式：`.rad` = 文本采集参数头；`.rd3` = int16 小端二进制回波数据；`.cor` = 逐道 RTK 轨迹（经纬度 + 时间，14 字段空格分隔；实现阶段复核：亚秒字段样例为 3 位毫秒，解析兼容更长精度） |
| RTK | 厘米级高精度 GPS；样例轨迹存在 ±1.43 m 横向抖动，显示前需平滑（§5.4） |
| AGC / 增益 / 深度白化 | 深层回波天然微弱，按深度放大信号才能看见深目标；AGC（自动增益控制）为默认显示模式（§5.4） |
| 阈值检测 / 候选标记 | 自动找出 B 扫描中"亮得反常"斑块的算法；**输出仅是候选**，漏检与过检均已实测存在（§5.4），人工复核为必需环节 |
| P99.5 自适应阈值 | 取单通道图像亮度 99.5% 分位数作门限，只保留最亮 0.5% 像素；各通道阈值差异大，必须逐通道自适应（§5.4） |
| 形态学膨胀 / 连通域 | 把邻近亮像素合并成块的图像处理步骤（15×9 核），过小的碎块（<15 px）丢弃 |

### A.4 本功能使用的样例数据

泰安测试 2025-11-13 采集，MALA 格式，共 65 个文件（32×`.rad` + 32×`.rd3` + 1×`.cor`）约 235MB，文件平铺于同一目录，命名形如 `<前缀>_<H|L>_<TnRm>_<序号>.rad/.rd3`，轨迹文件为 `<前缀>_001_RTK.cor`。数据经外部路径引用（默认 `/mnt/d/工作/排弹/数据集/001`，宏 `GPR_SAMPLE_DATA_DIR`，见 §5.5），**只读、不入库**。

## 附录 B. 数据层组件详解与协作流程

> 本附录用通俗语言解释 §5.2 五个组件各自"为什么存在、干什么、怎么干"，以及它们如何串成完整链路；API 契约以 §5.2 与源码头文件注释为准。

### B.1 组件职责详解

**GprRadarHeader —— 采集参数头解析器（快递面单）**
`.rd3` 是一堆无格式的二进制数字，没有头文件就不知道每道多少样本、怎么把样本序号换算成米深度。本组件读取 `.rad` 文本键值对（实测冒号分隔，兼容等号），提供 `samples()`、`timeWindowNs()`、`distanceIntervalM()` 及 `depthForSample()` 两程时间深度换算。`.rad` 中 `ANTENNAS:800` 与实测主频矛盾，原样保留但**不作频率依据**（§5.4）。

**GprBScanData —— B 扫描数据懒加载读取器**
单个 `.rd3` 约 7.5MB（7297 道 × 512 样本 × 2 字节），全数据集 235MB 不能一次读进内存。本组件按需读盘：界面要哪一道，就在文件里定位到那一道读哪一道，并保留 8 道的 LRU 缓存（最近用过的留住、最久没用的淘汰）避免反复读盘。另负责逐通道 t0 估计 `firstBreakSample()`：统计每道开头一小段纯噪声的均值与波动，找第一个显著超出噪声的样本；找不到则退化为"信号变化最陡的位置"；对全部道各估一次取中位数并缓存。

**GprDataset —— 数据集目录扫描器**
样例目录平铺 65 个文件。本组件扫描目录，识别出有哪些天线组（H/L）、每组有哪些通道、`.rad`/`.rd3` 是否成对齐全（孤儿文件不计入）、找到轨迹文件（优先 `*_RTK.cor`），并报告缺失通道清单（如 `H/T2R3`）。界面打开数据集时先问它"这批数据完整吗？能看哪些通道？"，缺失通道在切换器中禁用（§3.2）。

**GprTrack —— RTK 轨迹解析器**
读取 `.cor`，回答"第 N 道信号是在哪个经纬度、什么时间采集的"：道号与 `.rd3` 道 1:1 对齐（§5.4 已断言），缺行线性插值，RTK 抖动用高斯平滑压制（默认 σ=500 道 ≈10 m；σ=3 m 已被预研证明不足，见 §9 待确认项 6）；时间戳内部统一 UTC 存储，本地显示由调用方转换。阶段 3 人工确认可疑目标后，靠它把"道索引"换算成地图上的经纬度红点。

**GprThresholdDetector —— 阈值候选检测器**
对一张 B 扫描自动圈出可疑亮斑，输出候选列表（道索引、样本/深度、幅度、尺寸）。管线（参数经 §5.4 预研验证）：去直流 → t0 截取 → 横向背景去除（±50 道滑窗均值，抹平层界面、凸显点目标）→ 滑动 RMS 包络 → 深度白化（增益线性升至最深 10×）→ 逐通道 P99.5 自适应阈值 → 15×9 形态学膨胀聚集 → 连通域筛选（≥15 px）→ 候选列表。**安全边界：输出仅是候选标记，必须人工看图复核（确认/误报）后才进入目标体系**——漏检（弱事件）与过检（层界面条带）均已实测存在（§5.4）。

### B.2 协作数据流

```text
GprDataset 扫描目录（这批数据有什么？缺什么？）
   └→ 选定 H 组某通道
        ├→ GprRadarHeader 读 .rad（512 样本 / 110 ns / 0.02 m，提供深度换算）
        ├→ GprBScanData 开 .rd3（懒加载读道，先算 t0 校正）
        │     └→ 雷达页把 7297 道画成 B 扫描伪彩图（§6.2）
        └→ GprThresholdDetector 圈候选亮斑
              └→ 疑似目标列表面板，人工逐条看图复核（§3.1 步骤 6-9）
                    └→ 人工点【确认目标】
                          └→ GprTrack 查该道经纬度
                                └→ 注入统一目标列表 + 2D 地图红点（标注 [模拟]）+ 操作日志
```

### B.3 安全与边界（复述正文，便于查阅）

- 阈值检测输出仅为候选，人工复核闭环（确认/误报）为必需环节（§1.2、§5.4）。
- 全部 GPR 展示数据与目标标注 [模拟] / [GPR自动检测]（§6.4）。
- 样例数据只读、外部路径引用、不入库（§2.1、§5.5）；不接真实雷达设备（§2.2）。
