# 真实 M4E 无人机数据接入

状态：Approved（2026-10-10 用户批准）
关联产品需求：REQ-012（requirements/REQ-012.md）
关联版本：待确认

## 1. 问题与目标

### 1.1 问题

- REQ-009 已实现态势演示链路（`DroneTelemetrySimulator` 模拟遥测 + `VideoStreamPanel` 本地视频 + 检测推算目标坐标），但全部为本地模拟数据，客户端无真实无人机数据入口。
- 同事 MSDK App 现行数据出口（自定义 TCP 5888/5889 + RTSP）与现场内网链路格式（Cloud API 物模型 MQTT + 链路视频，见开工包接口规格）不一致，客户端与 EMQX/视频服务/PostgreSQL 之间无连接。

### 1.2 目标

真实 M4E 数据经内网链路进入客户端态势页：真实遥测驱动地图航迹，实时视频进视频区，HMS 事件入告警；REQ-009 模拟链路保留为可切换、互斥的数据源。

### 1.3 与外部计划的关系及范围裁决

本设计是开工包《M4E对接实施计划V3-MSDK路线》的**客户端侧对应设计**。App 工程已由同事移交（2026-10-10 用户确认）：`D:\工作\排弹\测试数据\Test` 为独立 git 仓库，含《UAS项目交接文档.md》（三通道协议规格、六项安全缺口、已验证结论）；App 侧改造改由本项目接续承担，代码不收入本仓。对开工包的评估结论与计划修订建议见 `.omo/plans/20261009-m4e-integration-kickoff.md`。

范围裁决（2026-10-09 用户确认）：**不含激光测距打点目标**。开工包 `measure_target_*` 字段系从 DJI 数据能力反推，上游来源资料（SRS/SDD/硬件规格书）无此需求；目标坐标来源保持 REQ-009 检测推算路径。视频链路制式已裁决：一期 RTSP 直连（见 §9-2）。遥测/告警链路维持 MQTT + Cloud API 物模型设计（2026-10-09 用户确认；否决"维持 App 现状 TCP 5888 直连"最省方案——HMS 告警需 QoS 1、TrackStore/多消费者订阅解耦、Cloud API 报文标准利于 V2 回退；开发用模拟链路同为 MQTT 仅附带便利，非裁决依据）。开工包定位（2026-10-09 用户裁决）：降为参考材料，不合理处直接抛弃——SRS 不进真实链路、对接操作指南作废、部署物不收编（本仓自写极简 compose）；接口报文规格作为双方契约收编本仓 `docs/interfaces/`（见 §9-5；2026-10-10 治理裁决自 `deploy/` 迁址）。

### 1.4 与 REQ-009 的关系

REQ-009（`Implemented`）不取代、不降级：其模拟遥测/视频/目标推算链路改造为本功能"模拟数据源"实现，真实接入是并列的"真实数据源"。REQ-009 已实现的地图、视频面板、四区同步机制全部复用。

## 2. 范围与非目标

### 2.1 范围（本仓）

- **数据源抽象**：遥测/视频/事件三类数据源接口；模拟源（现有 REQ-009 实现）与真实源（内网链路）双实现；任务开始前互斥切换。
- **MQTT 订阅接入**：订阅 `thing/product/+/osd`（QoS 0）与 `thing/product/+/events`（QoS 1），解析 Cloud API 物模型报文（`tid/bid/timestamp/gateway/data` 信封）。
- **链路视频**：视频区播放内网链路实时视频（一期 RTSP 直连遥控器，App 视频零改动；视频源为配置化 URL，面板协议不感知，演进见 §9-2；HUD-only 叠加不变）。
- **真实航迹**：态势地图按 OSD 经纬度实时显示无人机位置与航迹（复用 REQ-009 地图链路）。
- **HMS 事件**：`events` 主题 → 告警/日志区，含级别映射。
- **部署物**：仓根 `docker-compose.yml` 自写极简 compose（EMQX；PostgreSQL + PostGIS 待 §9-4 裁决后纳入，schema 参考开工包字段设计）与接口报文规格文档（双方契约，收编自开工包接口规格并自行维护，位于 `docs/interfaces/`）；`scripts/sim_telemetry.py` 留作开发/CI 测试工具（注明来源），不作验收依据（见 §9-5）。
- **数据源标识**：真实/模拟数据源 UI 常显区分标注（见 §6）。

### 2.2 非目标

- **App 侧改造**：出口层替换与字段补采在移交的 Test 工程（独立 git 仓库）进行，由本项目承担，代码不收入本仓（2026-10-10 用户确认）。
- **本功能不含任何下行指令**：仅上行数据接入；5889 反控链路不移植，客户端代码层不存在控制发布路径。直接飞行控制（杆量/起降/云台等实时操控）为安全边界持续禁止项；航迹规划等任务设置类指令属产品能力，下发至真实无人机为后续独立功能（2026-10-09 用户厘清表述）。
- **激光测距打点目标**：用户已裁决不需要（见 §1.3）；schema 中 `laser_targets` 表保留不启用。
- **识别/规划/排弹阶段功能**：各自独立功能，不在本设计。
- **检测链路改造**：`DetectionEngine` 与真实视频源的对齐为后续独立功能；本功能内目标表行为不变（沿用 REQ-009 检测推算，真实链路下推算输入为真实遥测）。
- **EMQX/视频服务鉴权与加密硬化**：内网阶段一可接受现状，外场前独立项。
- **Android 保活、多镜头并发推流**：App 侧事项。

## 3. 用户流程

1. 任务开始前，操作员在态势页数据源控件选择：**本地模拟**（默认）/ **真实链路**。
2. 选真实链路：客户端连接 EMQX 与视频服务，状态区显示连接状态与"真实链路"标识，本地模拟器停止。
3. 无人机起飞后：地图显示真实位置与航迹，视频区播放实时画面，HMS 事件入告警/日志。
4. 任务结束：断开链路；轨迹与事件已入库；可切回本地模拟。

## 5. 架构增量

- 新增数据源接口层（建议 `Core/Uplink`）：遥测源接口由 `DroneTelemetrySimulator` 改造实现（模拟源），`MqttTelemetrySource` 实现（真实源），二者输出同构内部遥测结构。
- 新增 `MqttUplinkClient`：订阅 osd/events，解析 Cloud API 物模型，输出内部遥测/事件结构。
- `VideoStreamPanel` 视频源抽象：本地文件（模拟）/ 链路 URL（真实，一期 RTSP 直连遥控器）；视频源配置化 URL、面板对协议与对端不感知（设计护栏，见 §9-2）；播放方案待选型（见 §9-3）。
- 新增 `EventIngest`：events → 告警/日志。
- 新增 `TrackStore`（可选开关）：PostgreSQL 轨迹库写入（`trajectory`/`events` 两表；`task`/`media` 表后续；`laser_targets` 表保留不启用，见 §1.3）。
- 部署物新增：仓根自写极简 compose（EMQX；PostgreSQL 待 §9-4）、`docs/interfaces/` 接口报文规格文档、`scripts/` 开发/CI 用模拟器（参考开工包 `sim_telemetry.py`，注明来源）；不收编开工包部署物（见 §9-5）。
- 与 ARCHITECTURE.md 关系：新增模块均为客户端侧数据接入层，不改现有状态所有权；安全边界变化（只读外部接入 + 轨迹库写入）随 REQ-012 批准生效并回写。

## 6. UI 增量

### 6.1 数据源切换控件

- 位置：态势页探测工具栏（现有 [重置][开始][结束] 按钮组）左侧新增数据源选择控件：`本地模拟`（默认）/ `真实链路`。
- 状态机：
  - `本地模拟`：现状行为不变（`DroneTelemetrySimulator` 驱动）。
  - `真实链路·连接中`：控件与开始按钮置灰，状态区显示"连接中…"；连接失败回退本地模拟并提示原因。
  - `真实链路·已连接`：开始按钮可用；本地模拟器停止；任务进行中（已开始）禁止切换，控件锁定。
  - `真实链路·断链`：数据流入暂停并提示，**不自动切回模拟**（防止真实/模拟数据混淆）；由操作员显式处置。

### 6.2 数据源标识

- 态势页中心区常显数据源徽标：模拟为现有"演示数据"标注样式不变；真实链路显示"真实数据"徽标（与模拟标注同视觉层级、不同色调，具体 token 实现对齐 `docs/ui/design-system.md`）；断链时变为"真实数据·断链"。

### 6.3 连接状态指示

- 数据源控件旁显示：MQTT 连接状态、视频拉流状态、最近 OSD 报文时间；>5s 无 OSD 报文判定数据停滞并提示。

### 6.4 告警与日志

- HMS events 按 level 映射现有告警级别（0/1/2 → 提示/警告/严重，映射表实现时冻结）；事件正文显示 HMS code + 文案；同步入日志区。

### 6.5 目标表

- 无新增列：目标坐标来源保持检测推算（REQ-009 现有路径）；真实链路下推算输入为真实遥测位姿。`DetectionEngine` 对真实画面的检测质量属后续独立功能验收范围。

### 6.6 施工细化（2026-10-10 用户裁决）

- **控件形式**：分段按钮 `[本地模拟 | 真实链路]` 并排，当前项高亮（选中态对齐现有导航/主色选中 token），宽约 180px、与 36px 工具栏同高；置于探测工具栏现有按钮组左侧。
- **视频 PiP 角标**：不加（用户裁决）；真实/模拟区分依赖中心区徽标常显 + HUD 遥测跟随。
- **HUD 数据跟随规则（补写）**：HUD 遥测值（LAT/LON/ALT/HDG）跟随当前数据源——真实链路显示真实 OSD，本地模拟显示模拟值；随数据源切换自动切换，无独立控件。
- **徽标与状态 token**（按 `docs/ui/design-system.md` 对齐；全部颜色+文字双编码，满足 UI.md §8 最小约束）：
  - 真实数据（已连接）：信息蓝 `#42A5F5`（`--color-tier-blue`，该 token 设计本意即区别于威胁色阶；不占用设备在线绿 `#4CAF50` 语义）
  - 真实数据·断链：`#FF5252`（`--color-status-error`）
  - 连接中… / 数据停滞：`#FFB74D`（`--color-status-busy`）
  - 模拟：现有"演示数据"标注样式不变
- **告警标注**：HMS 告警文字带 `[HMS]` 前缀（与 `[模拟]` 并列的来源双编码）；级别映射 0/1/2 → 提示/警告/严重，映射表实现时冻结。
- **文案定稿**：`本地模拟` / `真实链路` / `连接中…` / `真实数据` / `真实数据·断链` / `数据停滞（>5s 无遥测）`。
- **验收证据**：三视口截图（1280×720 / 1920×1080 / 3840×2160，延续 REQ-011 规则），含 1280×720 工具栏溢出让位检查。

## 9. 待确认事项

1. **MQTT 客户端库选型**：Qt MQTT 附加模块（需确认当前 Qt 5 版本与模块可用性）vs Eclipse Paho MQTT C++。**裁决（2026-10-10，用户确认）**：采用 **Eclipse Paho MQTT C++**——核查结果 Qt 5.15.15 无 QtMqtt 模块、apt 无 qtmqtt 包，apt 有 `libpaho-mqtt-dev`/`libpaho-mqttpp-dev`（纯 C++ 库，与 Qt 无 ABI 耦合）。
2. **视频链路制式（RTMP vs RTSP）—— 已裁决（2026-10-09）**：一期 **RTSP 直连**——客户端经现场 WiFi/内网直连遥控器拉流（复用 App 现有 Live555 RTSP 服务，H.264 已实测，延迟 ~0.5s，App 视频零改动）；起飞前确认遥控器 RTSP 地址可达。设计护栏：视频源为配置化 URL，播放面板不感知协议与对端（遥控器或服务器），后续协议切换不构成重写。演进路径（预留，按需触发）：需要集中录像/多席位时引入内网 MediaMTX/SRS——服务器主动拉 RTSP 并录像/分发（App 仍零改动）；仍不满足再改 App 推 RTMP（MSDK 原生支持，约 1–2 天，总切换成本约 2–3 天）。原对比表保留备查：

   | 维度 | RTMP 推流（开工包默认） | RTSP 拉流（App 现状） |
   |---|---|---|
   | 链路 | App → SRS:1935 → 客户端从 SRS 拉 | 客户端直连遥控器拉流 |
   | 延迟 | 1–3s | ~0.5s（App 侧已实测） |
   | 服务器录像 | SRS DVR 自动落 MP4（compose 已配） | 无（需客户端自录，或演进阶段由服务器拉流录制） |
   | 多席位分发 | 支持 | 不支持（遥控器连接数受限） |
   | App 改动 | 小（MSDK 原生 RtmpSettings） | 零 |
   | 前置依赖 | SRS 在线 | 客户端与遥控器同网段 |
3. **链路视频播放方案**：QMediaPlayer + GStreamer（工程量小、延迟偏高，两种制式均可用）vs FFmpeg/mpv 嵌入（延迟低、工程量大）——需原型验证后裁决。
4. **轨迹库写入授权范围 —— 已裁决（2026-10-10）**：随 REQ-012 批准授权生效（REQ-012 备注既定措辞：批准即构成轨迹库写入的明确授权）。范围按 §5：`trajectory`/`events` 两表，`TrackStore` 为可选开关（默认关闭）；`task`/`media` 表后续；`laser_targets` 表保留不启用。
5. **部署物 vendor 方式 —— 已裁决（2026-10-09）**：开工包降为参考、部署物不收编；本仓自写极简 compose（EMQX；PostgreSQL 待 §9-4），接口报文规格收编本仓 `docs/interfaces/` 并自行维护（双方契约）；模拟器留作开发/CI 工具（参考开工包 `sim_telemetry.py`，注明来源）。
6. **联调窗口 —— 已消解（2026-10-10）**：App 工程移交本项目接续，两端排期自主可控，无外部依赖；用户可手柄常驻开发调试，真机联调随时可进行。App 出口改造约 1–2 周（本项目承担，施工图见移交工程内《UAS项目交接文档.md》），完成后即进入真机联调（=REQ-012 验收）。
