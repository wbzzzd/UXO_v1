## 1. 问题与目标

当前客户端只有固定模拟场景和单目标状态流转，没有跑道损毁后的应急起降带规划能力。指挥席用户在跑道遭受打击后无法快速判断哪些区域仍可起降飞机，也无法比较不同修复程度下的可用跑道长度。

本功能的目标是在本地模拟损毁跑道上，用最大空矩形算法自动计算满足配置的模拟几何阈值的轴对齐可用矩形区域，并按修复程度递增给出多套方案，让指挥员权衡模拟修复时间与可用区域面积。本功能不构成真实起降或安全决策依据。

MVP 阶段全部基于本地模拟数据与纯算法计算，不依赖真实传感器、真实 AI、真实数据库或外部通信。本功能只关联 REQ-007，是 NEXT 六项草案（REQ-001~REQ-006）之外的独立候选，不属于当前 NEXT 切片。

## 2. 范围与非目标

**包含范围**：

- 跑道几何与损毁点的模拟数据结构，从本地 JSON 配置加载。
- 最大空矩形算法（Y 轴离散化 + X 轴扫描线），输出轴对齐 MOS 矩形。
- 修复程度递增的多方案框架，每档含已修复点列表、MOS 矩形、修复时间和修复难度。
- 弹坑体积按球体估算、未爆弹按固定工时估算的修复时间/难度模型。
- MOS 参数配置（最小起降尺寸、安全系数、档位数等）。
- 单方案 2D 基础可视化（跑道俯视图、缩放、平移）。
- 模拟损毁分布生成器（弹窗输入数量和范围，随机生成可复现的损毁场景）。

**非目标（本候选不实现）**：

- 真实设备控制、真实排爆或抢修动作、真实安全执行链。
- 真实 AI 推理、真实传感器接入、真实数据库写入、外部通信。
- 斜向起降带搜索（列为 P1，见第 4 节）。
- 修复优先级自动排序算法（列为 P1）。
- 3D 可视化与动态重规划（列为 P2）。
- 登录、角色切换、持久化。
- UXR 未爆弹识别（独立候选，本文档不覆盖）。

## 3. 用户流程

1. 指挥员在决策页打开 MOS 规划视图，看到当前模拟跑道和损毁点分布。
2. 指挥员通过工具栏"生成损毁场景"按钮，弹窗输入弹坑数量/半径范围和 UXO 数量/当量范围，系统按可配置随机种子生成可复现的模拟损毁分布。
3. 系统在当前档位（默认方案 1，不修复任何损毁点）上运行最大空矩形算法，标出可用 MOS 矩形。
4. 指挥员切换档位查看递进方案：每档修复更多损毁点，MOS 矩形面积单调非减，同时显示累计修复时间和综合难度。
5. 指挥员可调整参数（最小起降尺寸、安全系数、档位数），修改后重新规划。
6. 全程标注"模拟规划结果"，操作写入本地模拟操作日志。

P1 阶段补充：多方案叠加对比视图、修复优先级排序、斜向搜索、人工微调、规划报告。P2 阶段补充：3D 可视化、动态重规划。

## 5. 架构增量

本节描述相对 [`../ARCHITECTURE.md`](../ARCHITECTURE.md) 当前基线的预期增量。P0 已形成对应实现，但各条目的满足程度不同，具体差距见第 10 节；P1/P2 仍为 `Draft`，需在架构评审中确认。

- **数据结构**：新增跑道几何模型和损毁点模型（MOS-001），设计目标为从本地 JSON 配置加载，不接入真实传感器；坐标为本地米制，注释标注"模拟数据结构"。当前实现支持本地米制坐标、损毁点结构与规范化 JSON 序列化单向导出，但未实现 JSON 导入/重载/配置加载路径（详见 §10）。
- **算法服务**：新增最大空矩形计算（MOS-002），设计目标为 Y 轴离散化加 X 轴扫描线，纯本地计算、结果确定可复现。当前实现是简化版：X 轴投影加 Y 轴固定全宽 `[-halfW, halfW]`，未做完整 Y 轴 1m 离散化，`W_min` 不参与搜索边界确定（详见 §10）。
- **规划框架**：新增多方案递进规划（MOS-003），按档位调用算法服务，P0 用稳定前缀 tier 加简单规则指定修复点。当前实现已落地该框架。
- **估算服务**：新增修复时间/难度估算（MOS-005），弹坑按球体体积，参数可配置。当前实现已落地该估算器。
- **场景生成**：新增模拟损毁分布生成器（MOS-015），按可配置随机种子生成可复现分布。当前实现为确定性生成器 UI 加当前提交 fixture 的规范化导出，生成范围为 [-40, 40]，未达设计目标 [-250, 250]（详见 §10）。
- **接口边界**：设计目标要求服务类名或注释明确模拟语义。当前 `Core::MOS` 类型与源码注释明确其本地合成边界，不实现真实接入；现有类名不统一使用 `Mock` 前缀。

CURRENT 具体类、状态流和调用链以源码及 [`../ARCHITECTURE.md`](../ARCHITECTURE.md) 为准；来源草稿 [`../dev/architecture-mos.md`](../dev/architecture-mos.md) 仍为非权威历史输入。P1/P2 新增类与调用链须在对应需求获批后另行评审。
