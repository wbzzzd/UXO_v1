# 功能增量设计

本目录保存已经进入评审的功能增量设计。功能文档只描述相对四份核心基线的变化，不再为同一功能分别维护 PRD、SDD 和 UI 说明书。

四份核心基线：

- `../PRODUCT.md`：产品目标、范围、需求和路线。
- `../ARCHITECTURE.md`：模块、状态所有权、依赖和运行流程。
- `../UI.md`：信息架构、交互、页面状态和设计系统。
- `../DEVELOPMENT.md`：构建、测试、质量门禁和完成定义。

## 生命周期

1. `Proposed`：候选设计，可以讨论，不允许据此直接实现。
2. `Approved`：范围和验收标准已确认，可以生成 `.omo/plans/` 执行计划。
3. `Implemented`：代码和测试已完成，稳定变化已回写四份核心文档。
4. `Superseded`：已被其他方案替代，仅保留历史依据。

## 最小模板

```markdown
# 功能名称

状态：Proposed
关联版本：待确认

## 1. 问题与目标
## 2. 范围与非目标
## 3. 用户流程
## 4. 需求增量
## 5. 架构增量
## 6. UI 增量
## 7. 验收标准
## 8. 对核心文档的影响
## 9. 待确认事项
```

功能文档不得把 `TARGET` 或 `Proposed` 内容写成 `CURRENT`。研究报告只能作为证据引用，不能直接成为需求。
