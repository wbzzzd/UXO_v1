# MOS 决策界面 · 设计简报

> 给设计师朋友看的。5 分钟读完，告诉我哪里不对。

## 一、这是什么系统

排弹抢修指挥系统（Qt5/CMake/C++17 桌面客户端）。军用机场跑道被炸后，自动计算哪些区域还能起降飞机。

当前主界面布局：

```
┌──────┬──────────┬─────────────────────┬──────────┐
│导航栏  │ 目标列表   │     视频监控+操作日志   │ 3D态势图 │
│80px  │ 320px    │     (弹性)           │ 360~420px│
│      │          │                     │ +设备状态 │
│6个按钮 │ 搜索     │  4路监控画面          │ +决策建议 │
│      │ 目标表格  │  ────────────────    │          │
│态势   │ 任务表格  │  告警卡片 │操作日志    │          │
│探测   │ 设备表格  │          │按钮       │          │
│决策 ←│          │                     │          │
│设备   │          │                     │          │
│统计   │          │                     │          │
│配置   │          │                     │          │
└──────┴──────────┴─────────────────────┴──────────┘
```

- 导航栏"决策"按钮目前点了什么都不切换（信号发了但没消费）
- 这就是 MOS 该去的地方

## 二、要做什么

在导航栏"决策"按钮下做一个**起降带规划工作台**。点击"决策"后，导航栏保留不动，其余三栏全部替换为新界面。

### 核心需求

| # | 需求 | 说明 |
|---|------|------|
| 1 | 总体视图 | 跑道核心区 3000×500m 俯视全景（实景底图），叠加标注弹坑/未爆弹/已修复/MOS候选区域 |
| 2 | 多方案对比 | 算法输出多档位方案（不修复→修部分→修更多），每个方案展示局部裁剪视图+关键指标（面积、位置、修复时间、难度） |
| 3 | 最终选定 | 选中的方案显示详情和修复优先级清单，确认后执行 |
| 4 | 2D 自绘 | QPainter 手绘所有标注图层，支持缩放平移 |
| 5 | 深色主题 | 背景 #1E1E1E，指挥系统风格 |

### 不需要的东西

- 不需要 3D 渲染（MOS 分析是纯 2D 问题）
- 不需要目标列表/任务列表（决策场景不看那些）
- 不需要视频监控（这是分析面板，不是监控台）

## 三、尝试过的布局方案

### 方案 A（已放弃）：上下堆叠

```
┌─────────────────────────────────────┐
│ 工具栏                               │
├─────────────────────────────────────┤
│ ① 总体视图（230px 高）               │ ← 太扁，跑道的空间感丢了
├─────────────────────────────────────┤
│ ② 三张候选卡片横向排列（160px 缩略图）  │ ← 像报表，不像对比
├─────────────────────────────────────┤
│ ③ 选定方案                           │
└─────────────────────────────────────┘
```

**问题**：总体视图太扁；候选卡片并排太碎；整体像表单堆叠，不是工作台。

### 方案 B（当前）：左65% + 右35%

```
┌──────────────────────────────────────────────────┐
│ 工具栏                                             │
├──────────────────────────┬───────────────────────┤
│                          │ ② 候选方案卡片（竖排）     │
│  ① 总体视图               │ ┌─────────────────┐   │
│  跑道核心区俯视全景         │ │ 方案1 缩略图+指标  │   │
│  (填满左侧 65%)           │ ├─────────────────┤   │
│                          │ │ 方案2 缩略图+指标  │   │
│                          │ ├─────────────────┤   │
│                          │ │ 方案3 缩略图+指标  │   │
│                          │ └─────────────────┘   │
│                          ├───────────────────────┤
│                          │ ③ 选定方案详情+优先级   │
│                          │ (固定在右下)            │
└──────────────────────────┴───────────────────────┘
```

**问题**：右侧面板竖向空间紧张，候选多时需滚动；布局平衡感还需要优化。

### 方案 C（未实现）：三栏嵌入总览

```
总览大图按跑道长方向铺满上半区域，候选/选定区域横向排列在下方，类似视频剪辑软件的时间轴布局。
```

## 四、已经确定的设计决策

| # | 决策 |
|---|------|
| 1 | 入口通过导航栏"决策"按钮，替换除导航栏外全部面板 |
| 2 | 主面板不叫"MOSPanel"，叫"决策工作区" |
| 3 | 总体视图 3000m 跑道长向为水平轴，500m 宽向为垂直轴 |
| 4 | 弹坑红色、未爆弹黄色、已修复灰色打勾、MOS 矩形绿色半透明 |
| 5 | 所有参数默认值允许人工改，标注"示例值" |
| 6 | 档位切换：方案1(不修复)→方案2(部分修复)→方案3(修复更多)，数量可配 |
| 7 | 修复时间基于弹坑体积÷回填速率+UXO固定工时，标注"模拟估算" |

## 五、想让你帮忙判断的

1. **布局方向**：方案 B 的 65/35 分栏合理吗？还是应该考虑其他结构（比如总览全屏、候选卡片浮层、选定结果侧边抽屉）？

2. **信息密度**：候选卡片里要放多少指标？面积/尺寸/时间/难度/安全余量/需排除损毁——8 项会不会太多？怎么精简？

3. **总体视图的标注层级**：7 层（背景→跑道→弹坑→UXO→已修复→MOS矩形→文字标注），会不会视觉太乱？有没有更好的分层或过滤方式？

4. **选定方案的呈现**：当前做法是"摘要 + 修复优先级列表 + 三个操作按钮"——这个信息结构对不对？

5. **档位切换交互**：方案1→2→3 是按钮组还是下拉框还是滑块？每切换一次要重新跑算法，过渡动画或 loading 状态怎么处理？

6. **视角/缩放**：跑道是 3000×500m 的长条，屏幕是横向的。默认视图应该是"完整显示全跑道"还是"自动聚焦到当前方案区域"？

7. **空状态**：没有损毁数据（首次进入）、没有可用起降带（算法跑不出结果）——这两种情况怎么显示？
