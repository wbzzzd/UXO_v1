## 1. 项目信息

- **项目名称**：UXO_v1 排弹抢修指挥系统
- **技术栈**：Qt 5 / CMake / C++17 桌面客户端，目标程序 `UXOMissionControl`
- **MVP 约束**：仅允许本地模拟、只读分析、接口占位；禁止接真实设备/真实 AI/真实数据库写入（见 `AGENTS.md` 安全边界）
- **功能定义**：跑道受损后自动规划满足配置的模拟几何阈值的可用区域，输出多方案递进规划结果；不构成真实起降或安全决策依据

---

## 2. 产品目标

> **v2 修订：多方案递进选址与修复规划** -- 基于最大空矩形算法，叠加修复程度递增（0->部分->更多）的多方案框架，每档重算起降带并估算修复时间/难度。算法优先实现可用版本，修复优先级排序和多方案可视化对比 UI 放 P1。
>
> **V2.1 修订要点（2026-07-29）**：1) P0 不做斜向搜索，P1 新增斜向需求 MOS-016；2) 明确跑道道面 50m 与核心区域 500m 的关系；3) 修复优先级排序 MOS-004 从 P0 移至 P1；4) 弹坑体积 P0 按球体计算 V=4/3×π×r³；5) P0 使用模拟本地坐标，P1 做真实坐标映射；6) P0 新增模拟损毁分布生成器需求 MOS-015。

| 编号 | 产品目标 | MVP 阶段定位 |
|------|---------|-------------|
| MOS-G1 | 在受损跑道模型上，用最大空矩形算法自动计算满足配置的模拟几何阈值的轴对齐可用矩形区域，输出坐标、尺寸 | 模拟数据驱动，本地纯算法计算（Y 轴离散化 + X 轴扫描线），不依赖真实传感器，不构成真实起降或安全决策依据 |
| MOS-G2 | 提供"修复程度递增"的多方案递进框架 | MVP 用模拟修复工程量估算，每档为"已修复点子集 + MOS 位置 + 修复时间 + 修复难度"的完整方案 |
| MOS-G3 | 按对起降带选址影响大小对受损点排序 | 修复优先级排序放 P1；P0 每档修复点由人工指定或简单规则 |

## 3. 用户故事

| 编号 | 用户故事 |
|------|---------|
| MOS-US1 | 作为指挥员，我希望系统能在受损跑道上自动标出一段可用的应急起降带（不修复任何受损点），以便我快速判断当前跑道是否还能起降飞机。 |
| MOS-US2 | 作为指挥员，我希望系统给出"递进修复"的多套方案（不修复 / 修一部分 / 修更多），每套都标注起降带位置和对应的修复时间、修复难度，以便我权衡"修多久"与"能起降多长的跑道"。 |
| MOS-US3 | 作为指挥员，我希望系统按"对起降带选址影响大小"对受损点排序，优先列出最该先修的位置。（P1 实现） |
| MOS-US4 | 作为指挥员，我希望能在一个对比视图里看到各方案起降带位置的变化趋势。（P1 实现） |
| MOS-US5 | 作为操作员，我希望能配置目标机型最小起降尺寸、安全距离系数，以及递进档位数（默认3档）。 |
| MOS-US6 | 作为操作员，我希望能通过弹窗输入弹坑和未爆弹的数量、大小范围，系统随机生成损毁分布，以便我快速构造演示场景测试算法效果。 |

## 4. 需求池

### P0 - MVP 必须有的最小可用闭环（算法优先）

| 需求编号 | 名称 | 描述 | 验收标准 | SRS 对应 |
|---------|------|------|---------|---------|
| MOS-001 | 跑道与损毁模型 | 定义跑道几何数据结构和损毁点数据结构。弹坑影响半径含可见弹坑半径 + 结构损伤扩展区；未爆弹影响半径 = 模拟殉爆安全距离 D = K × W^(1/3)，其中 W 为模拟 TNT 当量（kg）。**坐标系约定：原点为跑道一端中心，x∈[0,3000] 沿跑道长度方向；50m 硬质道面为 MOS 搜索带，y∈[-25,25]；500m 损毁分布核心区（含道面两侧泥土区）y∈[-250,250]，障碍物可分布在 500m 核心区内，但 MOS 搜索区域限定在 50m 道面内。P0 使用模拟本地米制坐标系，不做经纬度转换；P1 再做真实坐标映射。** | 1) 跑道模型可从 JSON 配置加载；2) 损毁点含本地坐标(m)、类型、半径(m)、是否已修复、来源标注；3) 数据结构有中文注释标注"模拟数据结构"；4) P0 坐标为本地米制，不涉及经纬度 | 新增 |
| MOS-002 | 最大空矩形算法 | 给定跑道矩形和"未修复"损毁点集合，计算满足最小尺寸约束的最大轴对齐空矩形。约束：MOS 矩形不与任何未修复损毁点影响圆相交；**P0 仅轴对齐（平行）搜索，不支持斜向（斜向搜索列为 P1 MOS-016）**。MVP 用 Y 轴离散化 + X 轴扫描线方法，MOS 搜索区域限定在 50m 道面带（y∈[-25,25]）内。 | 1) 输入跑道道面 3000×50m + 5 个模拟损毁点，输出至少 1 个满足尺寸约束的 MOS 矩形；2) MOS 矩形与所有未修复损毁影响区无交集；3) 无法找到时返回"无可用区域"并说明原因；4) 纯本地计算；5) 同一输入结果确定可复现，面积相等的候选按确定性规则打破并列（先按 y 起点升序、再按 x 起点升序）；6) Y 轴步长 1m，在 50m 道面带（y∈[-25,25]）上对应 50 个采样点 | 新增 |
| MOS-003 | 多方案递进规划框架 | 在"修复程度递增"的多个档位上分别调用 MOS-002 计算起降带。**P0 每档修复哪些障碍物由人工指定或简单规则（如按影响面积从大到小），不使用复杂优先级排序算法（MOS-004 移至 P1）。** 档位数可配置（默认3）。 | 1) 默认输出方案1/2/3 共 3 个递进方案；2) 每个方案含"已修复点列表、MOS 矩形、修复时间、修复难度"；3) 档位越高 MOS 面积不减小（单调非减）；4) 档位数可调（2~5）；5) 纯本地、确定性，并列候选按确定性规则打破；6) P0 简单规则，P1 接入 MOS-004 | 新增 |
| MOS-005 | 修复时间/难度估算 | **弹坑体积 P0 按球体计算 V = 4/3 × π × r³（r 为可见半径），修复时间 = V ÷ 回填速率；未爆弹按固定工时估算。精确体积计算方法放 P1。** | 1) 每个损毁点可独立估算修复时间+难度；2) 弹坑体积用球体公式 V=4/3×π×r³；3) 每个方案汇总累计修复时间与综合难度；4) 参数可从 JSON 配置；5) 标注"模拟估算" | 新增 |
| MOS-006 | MOS 参数配置 | 可设置：L_min、W_min、安全系数 K、弹坑扩展系数、递进档位数、修复时间/难度估算参数。**P0 不含修复优先级权重参数。** | 1) 参数可通过 UI 或 JSON 修改；2) 修改后重新规划；3) 有合理默认值（L_min=460m, W_min=15m, K=1.5, 档位数=3）；4) 默认值标注"示例值，待业务确认" | 新增 |
| MOS-007 | 单方案 2D 基础可视化 | 2D 跑道俯视图展示当前档位规划结果。支持缩放和平移。 | 1) 跑道、损毁区、MOS 区域用不同颜色区分；2) MOS 矩形标注坐标和尺寸；3) 已修复点有区别标记；4) 标注"模拟规划结果·方案N"；5) 可缩放和平移 | 新增 |
| MOS-015 | 模拟损毁分布生成器 | 弹窗界面，用户输入弹坑数量/大小范围、UXO 数量/当量范围，系统在损毁分布核心区（x∈[0,3000]，y∈[-250,250]，即 3000m×500m）内按可配置随机种子确定性生成分布。结果可保存为模拟场景 fixture JSON（非运行态持久化）。交互：决策页工具栏"生成损毁场景"按钮。 | 1) 可输入弹坑数量和半径范围；2) 可输入 UXO 数量和当量范围；3) 生成结果在跑道图即时显示；4) 可保存为模拟场景 fixture JSON（本地输入，不写运行态数据库）；5) 标注"模拟随机生成"；6) 随机种子可配置，同一种子与输入产生同一分布 | 新增 |

## 7. 安全边界声明

- 所有 MOS 规划基于本地模拟损毁数据，标注"模拟规划结果"，不接入真实传感器、不执行真实排弹或抢修动作。
- 模拟数据仅存在于内存或本地模拟场景 fixture JSON（如 `mos-demo-scenario.json`、`mos-params.json`）；这些 fixture 是本地模拟输入，不是运行态持久化，MVP 不写入任何运行态数据库。
- 安全距离公式参数可配置，修改参数仅触发本地模拟算法。
- 模拟损毁分布生成器（MOS-015）按可配置种子确定性生成，数据标注"模拟随机生成"。
