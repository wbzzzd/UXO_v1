# REQ-014: 统计页数据平台可视化

| 字段 | 值 |
|------|-----|
| ID | REQ-014 |
| 所属 | 独立候选（不并入 NEXT 切片） |
| 状态 | `Implemented`（2026-10-13 验收通过） |

## 能力

新建统计页（导航"统计"当前为占位项），作为 REQ-012 Integration 适配器的首个应用侧消费方，对本地数据平台真实数据做**只读**可视化统计：五实体总数概览卡片、状态/类型分布图（词表维度）、时间趋势折线（按日分桶）、告警处理统计（级别分布+处置占比）、五实体明细列表（过滤+分页）。实例不可用时显示显式不可用态与重试入口，不以模拟数据冒充真实数据。

## 解决的当前缺口

- 导航栏"统计"（index 4）为占位项：页面栈只有态势/探测/决策三页，`MainWindow::onNavigationChanged` 对 index 4 回落态势工作区，统计能力为零（SRS v1.0 §3.7.2"统计分析插件"仅为上游来源，从未立项）。
- REQ-012 适配器库（Implemented）仅有测试消费方，未接入应用装配；本需求确立首个应用侧使用场景，使用户 2026-10-12 明确的"有了数据库之后就可以有基础的应用了，暂时先在这个页面使用"落地。
- 统计可视化是数据平台价值的最低风险落点：只读、单页、不触碰模拟链与既有三页。

## 统计项清单（做完后用户可见信息）

全部数据来自本地数据平台真实数据（只读）；词表桶标签经 VocabularyCache 取 `name_cn`；除注明外均为当前手动刷新快照值。

**A. 概览卡片（5 张，主指标 = 对应实体列表 `meta.total`）**

| 卡片 | 主指标 | 副指标（全量拉取后本地推导） |
|------|--------|------------------------------|
| 隐患目标 | 目标总数 | 今日新探测数（`detect_time` 当日）、平均置信度（`confidence` 均值） |
| 设备 | 设备总数 | 近 24h 有在线记录数（`last_online_time`） |
| 处置任务 | 任务总数 | 今日新建数（`create_time` 当日） |
| 告警 | 告警总数 | 未处置数（`is_handled=false`） |
| 检测记录 | 记录总数 | 异常数（`has_anomaly=true`）、平均置信度 |

**B. 状态/类型分布图（10 张，词表维度分桶，各桶合计 = 对应实体总数）**

- 目标 3 张：类型分布（12 桶 `target_type`）、状态分布（7 桶 `target_status`）、威胁等级分布（5 桶 `threat_level`）
- 设备 2 张：类型分布（8 桶 `device_type`）、状态分布（7 桶 `device_status`）
- 任务 2 张：类型分布（5 桶 `mission_type`）、状态分布（9 桶 `mission_status`）
- 告警 1 张：级别分布（5 桶 `alarm_level`）；`alarms.type` 为自由文本（词表待定），本轮不做告警类型分布
- 检测记录 2 张：模型类分布（9 桶 `class_name`）、复核状态分布（3 桶 `detection_review`）

**C. 时间趋势折线（近 30 天、按 UTC 日分桶、空日补 0）**

- 目标探测数（`detect_time`）
- 检测记录数（`analyzed_at`），可叠加其中异常数线
- 告警数（`create_time`）
- 设备/任务登记数（`create_time`）可切换展示，默认隐藏

**D. 告警处理统计**

- 告警级别分布柱状图（同 B 告警图）
- 处置占比饼图：已处置/未处置（`is_handled`）+ 未处置数
- 平均处置时长：已处置且 `handle_time` 非空告警的 `handle_time − create_time` 均值

**E. 明细列表（5 个实体 tab，服务端分页，页大小 20，过滤器映射契约 §7）**

| tab | 主要列 | 可用过滤 |
|-----|--------|----------|
| 目标 | 类型/威胁等级/状态（词表名）、经纬度、置信度、探测时间、备注 | `type`/`status`/`threat_level` |
| 设备 | 名称、类型/状态（词表名）、电量、最近在线、创建时间 | `type`/`status` |
| 任务 | 类型/状态（词表名）、优先级、指派人/执行人、计划起止、创建时间 | `type`/`status`/`target_id`/`device_id` |
| 告警 | 级别（词表名）、类型（原文）、消息、是否处置、创建时间 | `level`/`is_handled`/`target_id`/`device_id` |
| 检测记录 | 模型类、置信度、异常、复核状态（词表名）、分析时间、关联目标 | `review`/`class_name`/`has_anomaly`/`target_id` |

## 实现事实

- 页面与接线：`StatisticsView`（三态页：加载中/显式不可用+重试/就绪）加入页面栈 index 4，`MainWindow` 接线导航 case 4 触发 `triggerLoad()` 进页加载；index 3 实现时为设备占位空页垫位（2026-10-20 合并 main 后已由雷达页 `GprView` 占用，REQ-013；导航"设备"项相应改名"雷达"）。
- 控制器：`StatisticsController` 为 MainWindow 层首个真 `QThread` 控制器——worker 懒建并独占 HttpClient/DataPlatformApi/VocabularyCache（`QNetworkAccessManager` 线程亲和，构造/使用/销毁均在 worker 线程），结果以值拷贝信号 `snapshotReady`/`listReady`/`snapshotFetchFailed`/`listFetchFailed` 回投 UI 线程，revision 守卫丢弃陈旧快照，析构先 `quit` 再 `wait`。
- 快照与聚合：`StatisticsSnapshot` 值类型（恰 5 卡片、10 分布、6 趋势、告警汇总与词表中文名副本）；`StatisticsAggregation` 纯函数层——契约 v1 无聚合端点，客户端 `page_size=100` 循环翻页全量拉取后本地聚合，设计假设单实体 ≤ 约 1 万行。
- 明细与刷新：5 页签（目标/设备/任务/告警/检测记录）服务端分页 20 行/页，各页签首次激活懒加载；进页加载与手动刷新共用 `triggerLoad()`，已有数据时刷新失败仅行内提示（置灰不清空）。
- 构建：根 CMake `find_package` 增加 `Charts`，新增测试目标 `UXOMissionControlStatisticsAggregationTest`（ctest `statistics_aggregation`）；`MainWindow` 库新增 3 源 4 头并链接 `Qt5::Charts` 与 `Integration`。
- 只读边界：页面全部交互零写回；数据与词表仅经只读 GET 获取。
